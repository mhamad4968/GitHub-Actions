## 棄却された案 (Sonnet 直接書込相当 = §54-2-1 Sonnet 書込権限)

### 反 1: §54-5 そのもの = §52-3 Q6 と二重規制 (Sonnet 全面採用)

**棄却された案**: §54-5 Learning Boundary 新章として制定。

**棄却理由 (Sonnet 21:10)**: 「§52-3 v3 Q6 scope check が既に『承認スコープ外ファイル操作 = 即停止』を定義済み。AI が本番ファイルに触れるなら Q6 で止まる。§54-5 は Q6 の二重規制であり、ルール層の無駄な肥大化にすぎない」。

### 反 2: MCP 試験の物理的不可能性 (Sonnet 致命的盲点指摘)

**棄却された案**: メイン AI が「test-area/ 内に限定 + mcp.json 書換禁止」を提案。

**棄却理由 (Sonnet 21:10 致命的盲点)**: 「**MCP の試験は mcp.json への登録なしに不可能**。新 MCP を『test-area/ 内に限定』しても、MCP プロセスを起動するには必ず `~/.cursor/mcp.json` への記載が必要 — しかしそれはルール 2 で『厳格禁止』。つまり §54-5 は『MCP を試したいが登録してはいけない』という物理的矛盾を内包しており、**MCP 試行ユースケースに対してルール自体が機能しない**」。

### 反 3: 自律 vs 許可制の自己矛盾 (Sonnet)

**棄却された案**: メイン AI 「試験成功後に Tier B 投入 → 浜田裁定で本番反映」フロー。

**棄却理由 (Sonnet)**: 「浜田 21:08『自律優先』と『試験成功後は Tier B 投入 → 浜田裁定で本番反映』が直接衝突。AI が自律判断で試験成功と結論しても、昇格に浜田承認を要するなら **自律ではなく許可制** に逆戻りする」。

### 反 5: 代替案 = AI 自律学習権限完全廃止 (Sonnet 全面採用)

**Sonnet 提案**: 「『学習境界線』より **『AI への自律学習権限そのものを廃止』** のほうが論理的に一貫する。浜田が『この MCP 試して』と言った瞬間に例外発動なら、**実質すべての MCP 試行は浜田指示ベース**になる。ならば『AI が自発的に試す』というユースケースを正式に禁止し、Q6 scope check + 浜田明示指示のみで完結させるほうが、ルール数を増やさず整合性が高い」。
