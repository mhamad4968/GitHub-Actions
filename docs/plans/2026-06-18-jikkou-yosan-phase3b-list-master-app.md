## 1. AIチーム結論 — **v1 でリストマスタアプリを作設する（推奨）**

| 観点 | 固定ドロップダウンのみ（旧 Phase 3） | **リストマスタアプリ（推奨）** |
|------|-------------------------------------|-------------------------------|
| コード空白の後日入力 | 実行予算レコード行ごとにバラバラ | **マスタで一括登録** → 以降の選択で自動反映 |
| リスト追加 | 再デプロイ必要 | **kintone 上で追加** |
| Excel リスト正 | 初回取込のみ | **初回取込 + マスタが運用正本** |
| 687/688 先例 | — | **データ正本 + UI アプリ** と同型 |
| v1 工数 | 小 | **中**（+1 アプリ・取込スクリプト） |

浜田「リスト用マスタは作設したほうがいい」→ **採用**。

## 2. アプリ構成（v1 確定案）

| アプリ | 名称 | 役割 |
|--------|------|------|
| **M** | **【実行予算書】リストマスタ ver.01** | **コード表 + リスト** の運用正本 |
| **B** | **【実行予算書】ver.01** | 総括表・詳細表 UI（688 同型） |

**配置**: Space 56 / thread 60（687/688 と同スレッド）

```
コード.xlsx ──取込──┐
リスト.xls  ──取込──┼──► [M] リストマスタ
                    │
               REST 参照
                    ▼
               [B] 実行予算
```

## 3. リストマスタ M — データモデル

**1 レコード = リスト 1 行**（カテゴリで区別）

| フィールドコード | 画面ラベル | 型 | 備考 |
|-----------------|-----------|-----|------|
| `list_category` | カテゴリ | ドロップダウン | 下表 |
| `item_code` | コード | 文字列(1行) | **空欄可**（未決→後日入力） |
| `item_name` | 名称 | 文字列(1行) | 必須 |
| `item_sub_name` | サブ名称 | 文字列(1行) | 桁種別の「河川橋」等（任意） |
| `sort_order` | 表示順 | 数値 | Excel 行順 |
| `is_active` | 有効 | チェック | 無効化で非表示 |
| `source` | 出所 | ドロップダウン | `excel_import` / `manual` |
| `note` | 備考 | 文字列(1行) | |

### 3.1 カテゴリ `list_category`

| 値 | リスト列 | 実行予算での利用 |
|----|---------|-----------------|
| `order_branch` | 発注支社 | ヘッダ |
| `department` | 部門 | ヘッダ |
| `girder_type` | 桁種別 | ヘッダ（code= B 等, sub= 河川橋） |
| `unit` | 単位 | 仕様・原価・外注 |
| `tax_rate` | 消費税 | 原価行（code= 0.08 等） |
| `work_type` | システム入力工種 | 原価行 |
| `cost_category` | 種別 | 原価行 |

**工種と種別**: リスト上は別列だが **名称が対になる行** — M では **別レコード**（category で区別）。実行予算 UI で工種選択時に **同名の種別を提案**（Phase 4）。

## 4. 初回取込

| 項目 | 内容 |
|------|------|
| ソース | `実行予算書　書式.xls` — **リストシート** |
| 方法 | ワンショット REST 投入（687 初回データ同型） |
| コード空白行 | **名称のみでレコード作成**（`item_code` 空） |
| 再取込 | 既存 `item_name` 一致は **更新しない**（手入力コード保護）— 初回のみフル |

---

## 5. 実行予算 B との連携

| 操作 | 動作 |
|------|------|
| 画面ロード | M から有効行を取得（JS キャッシュ） |
| ヘッダ DD | カテゴリ別名称一覧 |
| 原価行・工種選択 | `work_type` 名称 → **工種コード自動**（M の `item_code`） |
| 原価行・種別選択 | `cost_category` 名称 → **種別コード自動** |
| M でコード空白 | 実行予算上も **空** — 作成者は **行上で仮入力可** |
| M でコード確定後 | **新規行**は自動反映。既存行は **そのまま**（v1） |
| 権限 | M=**管理者のみ**編集 / B=**現場責任者**（浜田 GO Q3 2026-06-18） |

**v1 では B の行コードを M へ書戻ししない**（マスタ更新は管理者が M で実施）。

---

## 6. 却下案

| 案 | 理由 |
|----|------|
| 固定 DD のみ継続 | コード後日入力・リスト追加が運用に合わない |
| カテゴリ別に M を 7 分割 | 管理分散 — **1 アプリ + category** で足りる |
| B 内サブテーブルでマスタ | 687/688 先例と異なり参照・権限が弱い |

## 7. Phase 4 への影響
