## §1. 背景・目的

### 1.1 背景

- 部署・支店単位の **メーリングリスト**（NTT BIZメール上の配信リスト）を **Excel 1 シート**で管理している。
- **人事**は毎月 1 日の発令時・新規リスト作成時にメンバー追加・削除を依頼する。
- **システム推進室**が Excel を更新し、**BIZメール管理画面**にも反映している。

### 1.2 共有メール（695/696）との違い（前提）

| | **共有メールアドレス（695/696）** | **メーリングリスト（本案件）** |
|--|-----------------------------------|--------------------------------|
| 用途 | アカウント名＋PW で Outlook 登録。**代表メール**として直接利用 | メールアドレスに **入れ子** で登録し **転送** する配信リスト |
| BIZメール | 共有メールボックス | リストメンバー登録 |
| メンバー表記 | （対象外） | **BIZメール** → `@` 前のアカウント名。**他キャリア/プロバイダ** → フルアドレス |
| PW | あり | **なし** |

### 1.3 目的

1. Excel と同等の台帳を kintone に置き、**日常操作は台帳**で行う（Excel は今後使わない）。
2. **kintone で整形・確認** → **BIZメール管理画面へ反映** の運用フローを確立する。
3. リスト **作成日・更新日** と **直近変更メモ**（追加/削除の差分）を残す。
4. **メンバー検索**（アカウント名/メールで所属リストを横断検索）・**印刷**・**Excel 出力**を v1 に含める。

### 1.4 スコープ外（v1）

| 項目 | 理由 |
|------|------|
| **695/696 との kintone 連携** | 別台帳・単独運用 |
| **595 社員マスタ連携（DB フィールド）** | v1 はメンバー ID 文字列のみ。氏名表示は将来拡張可 |
| **BIZメール API 自動同期** | 手動反映。kintone が正本台帳 |
| **メンバー個別の追加日履歴の永続蓄積** | v1 は **直近 1 回分の変更メモのみ**（Q1 確定） |
| **有償 kintone プラグイン** | 使用しない |

## §7. バリデーション・正規化

### 7.1 members_raw 正規化（保存時）

1. 全角カンマ `，` → 半角 `,`
2. 各要素の前後空白除去
3. 空要素除去
4. **末尾カンマ除去**
5. 重複メンバー（同一リスト内）は **警告表示** → 保存前に確認（自動 dedupe は v1 では行わず、確認ダイアログ推奨）

### 7.2 list_address

- 小文字化は **しない**（表示は Excel 通り）
- 登録時 **`@j-bis.co.jp` で終わること** を必須チェック
- **unique** — 重複登録不可（Q8-3）

### 7.3 メンバー表記（運用ルール・DB では強制しない）

| 種別 | 例 | 備考 |
|------|-----|------|
| BIZメール アカウント | `hamada-m`, `s-hashiba` | `@` なし |
| 社内フルアドレス | `f-omata@j-bis.co.jp` | 他リストをメンバーに含む場合あり（6 件） |
| 外部アドレス | `xxx@icloud.com`, `xxx@mitsubishi-autolease.com` | 7 リストに @ メンバー |

v1 では **形式バリデーションは緩め**（空白・カンマ整形のみ）。誤入力はシステム推進室が目視確認。

## §8. 運用フロー（確定）

```
人事から依頼（発令・新規リスト）
  ↓
システム推進室: kintone 台帳でメンバー編集（カンマ区切り貼り付け可）
  ↓
kintone 保存
  → updated_date 更新
  → last_change_memo 自動生成（直近 1 回分を上書き）
  ↓
一覧・詳細・検索・印刷で内容確認
  ↓
BIZメール管理画面へ同内容を反映して保存
```

- **正本台帳**: kintone（Excel は移行後使わない）
- **実配信設定**: BIZメール管理画面
- **照合（任意）**: 月次等、BIZ からコピー → kintone 貼り付けで実態確認

## §9. ダッシュ UI 要件（確定）

### 9.1 一覧

| 列 | 内容 |
|----|------|
| 操作 | 編集・削除（物理） |
| 利用部署 | |
| メールアドレス | |
| 利用用途 | |
| メンバー | **先頭 5 名**を **`/` 区切り**表示 + **「他 N 名」**（Q6-C） |
| メンバー数 | 自動計算 |
| 更新日 | |
| 直近変更メモ | |

**状態フィルタ（チップ/ボタン）**: **全数｜有効｜削除** — **初期表示は「有効」のみ**（Q7-1）。

### 9.2 詳細・編集モーダル

| 項目 | 内容 |
|------|------|
| 利用部署 | ドロップダウン（38 部署） |
| メールアドレス | `@j-bis.co.jp` 必須 |
| 利用用途 | 任意 |
| メンバー | **カンマ区切り 1 欄**（丸ごと差し替え・Q4-A）。**全文表示** |
| 備考 | 任意 |
| 作成日・更新日・直近変更メモ | 表示のみ（メモは保存時自動） |

**新規必須**: 利用部署・メールアドレス・初期メンバー（Q7-2）。

### 9.3 検索・絞込

| 機能 | 内容 |
|------|------|
| キーワード | `list_address` / `members_raw` / `purpose` を部分一致（空白 AND） |
| 部署 | 利用部署プルダウン（マスタ順） |
| **メンバー検索** | 例: `hamada-m` → **そのメンバーが含まれるリスト一覧**（Q5-2 **必須**） |
| 状態 | 全数 / 有効 / 削除 |

### 9.4 削除の 2 段階（Q8-2）

| 操作 | 内容 |
|------|------|
| **論理削除** | `status=削除` → 通常一覧（有効）から非表示 |
| **物理削除** | 誤登録のみ。確認ダイアログ必須（696 型） |

### 9.5 変更メモ自動生成（Q1 確定）

- 保存前 `members_raw` と保存後を **トークン分割比較**
- 追加: `{値}追加`、削除: `{値}削除` — **全角スペース区切り**
- 先頭に **JST 日付** `yyyy.mm.dd：`
- 例: `2026.07.07：hamada-m追加　kawada削除`
- **members_raw に変更が無い場合**はメモ **更新しない**（updated_date も据え置き可 — 実装時に仕様書追記）

### 9.6 印刷（Q6-A）

- **全リスト一括印刷**（部署マスタ順）
- **利用部署で絞り込み**可能
- メンバーは **`/` 区切り**で全文

### 9.7 Excel 出力（Q6-B）

- **現行 Excel 同型 1 シート**: 管理番号・利用部署・メールアドレス・利用用途・メンバー（**カンマ区切り**）
- PW **なし**
