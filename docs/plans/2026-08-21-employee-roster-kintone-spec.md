## 5. 同期・移行

### 5.1 初期突合

1. Excel「社員一覧」を読む（列: 事業所／部署名／役職／社員番号／社員名／メール）
2. キー候補: **氏名（`user_name`）＋所属（部署名）**
3. 一意ヒット → `employee_no`・雇用区分・兼務行・メールを 595 に反映（`emp_id` は触らない）
4. 0 件／複数件 → **曖昧リスト**を出し人手確定（`match_status`）
5. 確定ペアは **マッピング永続化**（氏名＋所属 → `employee_no` / 595 `$id`）。以降の定期同期はこれを優先（DeepSeek 盲点③）

### 5.2 595 → 名簿同期

1. **タイミング（確定）**: 595 **保存成功時に 1 人単位**で 776 へ upsert（即時・A方式）。**保存ごとの名簿全件 `list_sort` 振り直しはしない**（レスポンスのため。新規兼務は部署末尾の整数。隙間は許容）
2. 対象: `employment_category` ∈ {正社員, 準社員} かつ退職でない。それ以外・退職は 776 から削除
3. 本務行 1 件＋ `concurrent_posts` 各行を名簿へ upsert（キー: `source_595_id` + 行区分。兼務は作り直し）
4. 所属コード／名称の型差がある場合は **680 マスタで名称解決**してから名簿へ書く（DeepSeek 盲点①）
5. メールは 595 `mail` を名簿へ上書き同期
6. **並び `list_sort`**: 本務 = `595.sort` そのまま（**1=堀込社長**）。兼務は既存行の順を維持。**新規兼務のみ**当該部署の `list_sort` 最大＋1（末尾）。（旧: 保存のたび全件 1..N 再採番 → 廃止）
7. **兼務 `group_name`**: 日本語拠点名はコード化（本社→`honsya`、東北支店→`tohoku`、札幌/首都圏→`reform` 等）
8. **並列**: 776 名簿同期は 674／714／716 ミラーと **並列**実行（保存待ち短縮）

> `emp_id` は `emp_id_ref` への読取コピーのみ。上書き禁止。

### 5.3 兼務展開ルール（DeepSeek 盲点②）

- 595 **1 レコード** → 名簿 **複数行**になり得る
- 集計表は **本務／兼務を分離し、右に合計（本務＋兼務）**。各列は部署ラベル内で `source_595_id` DISTINCT。兼務は一覧・印刷にも出す

### 5.4 Excel 削除

- 条件: 移行完了＋浜田目視 OK＋曖昧リスト解消（または明示スキップ合意）
- それまで `C:\tmp\社員名簿（正社員・準社員）\社員一覧表.xlsx` は **削除禁止**
