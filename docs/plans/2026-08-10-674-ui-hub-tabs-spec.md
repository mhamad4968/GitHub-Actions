## 0. 目的・非目的

### 目的

- 機能追加で一覧がごちゃついた状態を、**役割（何をしたいか）で分ける**ことでシンプルにする。
- 色・階層を整え、利用者・管理者が「次に押すもの」を迷わないようにする。
- **台帳をメイン入口（ダッシュボード的）**にし、棚卸・管理は必要なときだけ開く。

### 非目的

- kintone **別アプリ**への分割（裏でアプリが違う、は**しない**）。
- SKYSEA 実配信・GPO・SG・新規案件化。
- 670 キャンペーン期間と年次期間の**完全統合**（既存どおり二系統ラベル維持・`2026-08-08-evening` O3）。
- 一度に編集ヘッダーまで全部壊す大改修（段階実施）。

## 2. 情報設計

### 2.1 一覧（`app.record.index.show`）— 3 タブ

```
[ 台帳 | 棚卸 | 管理 ]
        ↑ 既定（ダッシュボード入口）
```

| タブ | 誰向け | 置くもの | 置かないもの |
|------|--------|----------|--------------|
| **台帳** | 全員 | 次採番バー／キーワード・備考・並び／絞り込み・条件クリア／種別・ステータス等チップ／いまの条件・プリセット／リスト一覧作成 | 一括棚卸・未棚卸・棚卸状況アコーディオン／SKYSEA 管理ボタン群 |
| **棚卸** | 棚卸担当〜全員（閲覧可） | 期間ラベル（キャンペーン／年次の二系統）／一括棚卸／未棚卸一覧／棚卸状況一覧 | 日常検索の主戦場（＝台帳タブへ誘導）／SKYSEA 管理 |
| **管理** | **admin のみ表示** | SKYSEA対応一覧／SKYSEAクライアント削除対応（既存機能の移設） | 一般利用者向け検索・棚卸操作 |

**権限**: 管理タブは現行どおり LoginID `admin`（および既存 SKYSEA UI と同じ条件）のときだけタブ自体を出す。非 admin には **台帳｜棚卸** のみ。

### 2.2 編集・詳細ヘッダー（`#new-pc-ledger-buttons`）— 第2段

一覧タブとは別フェーズ（同時全面変更しない）。

| グループ | 例 | 表示 |
|----------|----|------|
| **主操作**（常時目立つ） | 入力支援／印刷／（詳細なら）棚卸・PC買替 | ボタン 1〜3 |
| **その他**（折りたたみまたはメニュー） | 自動生成／転用廃棄／登録ミス取消／全フィールドリセット | 初期は閉じる |

危険操作（廃棄・取消・リセット）は赤系＋既存 confirm を維持。

### 2.3 レコード画面とタブの関係

- タブは **一覧専用**。レコード詳細／編集を開いているときは従来どおりヘッダーバー。
- 一覧に戻ったとき、**直前のタブ**を復元（§3.2）。

## 3. 状態・URL・期間

### 3.1 フィルタ（探す条件）とタブ

- 既存 URL／hash パラメータ（`npl674kw` / `npl674note` / `npl674sort` / `query` / 標準 `q` 等）は **台帳タブの「探す」状態**として維持。
- **タブ選択は別キー**で持つ（推奨: `sessionStorage` + hash `npl674hub=ledger|inventory|admin`）。
- タブ切替でフィルタ条件を勝手に消さない。棚卸・管理タブでは「いまの条件」要約を小さく残し、変更操作は台帳タブへ誘導してよい。

### 3.2 既定・復元

1. 初回（キーなし）→ **台帳**
2. 同一セッション内で一覧再表示 → 直前タブを復元
3. 管理タブを開いたまま非 admin 相当になった場合 → 台帳へフォールバック

### 3.3 棚卸期間外の棚卸タブ

DeepSeek 案の「タブ全体グレーアウトで操作不可」は **採用しない**（状況一覧の通年確認を潰すため）。

| 要素 | 期間外 |
|------|--------|
| 棚卸タブ自体 | **表示する**（開ける） |
| 期間ラベル | 「現在は棚卸期間外」を明示（既存二系統ラベルと併記） |
| 一括棚卸・未棚卸・個別棚卸入口 | **非表示または disabled**（現行の period-gate と同趣旨） |
| 棚卸状況一覧 | **閲覧可**（通年） |

### 3.4 色・ビジュアル（案Bを全フェーズ共通言語に）

| トークン | 用途 |
|----------|------|
| `--npl-bg` | 帯背景（ごく薄いクールグレー） |
| `--npl-accent` | 主 CTA・選択タブ下線（スチールブルー〜ティール **1色**） |
| `--npl-muted` | 副ボタン・アウトライン |
| `--npl-ok` / `--npl-warn` / `--npl-danger` | 状態・注意・危険のみ |

禁止・回避:

- 紫グラデ／絵文字依存の意味付け／同格カラフルボタンの横並び
- 印刷テーマ色を画面に無秩序流用（印刷は既存 print tokens を維持）

コントラストは WCAG おおよそ AA を目標。色だけに頼らずラベル必須。

## 4. 段階（C-phased）

| Phase | 内容 | 目安 | 完了条件（要約） |
|-------|------|------|------------------|
| **P0** | 本仕様の浜田確認（文言・タブ名・権限） | 本日 | 仕様 GO |
| **P1** | 一覧: タブ骨格＋台帳／棚卸／管理への**既存部品の移設**＋共通色トークン | 数日 | 3タブ切替可・機能欠落なし・admin のみ管理 |

P1 完了時点で「ごちゃつき」の大半は解消する。P2 は独立して GO 可能。

## 6. リスクと対策

| リスク | 対策 |
|--------|------|
| 慣れた人のクリック位置が変わる | P1 でタブ内の部品順は現行に近く保つ／短い案内1行 |
| タブと URL フィルタの競合 | タブキー分離（§3.1）。フィルタ消去しない |
| 期間外に棚卸が使えなくなる誤解 | §3.3（タブは開く・操作だけ gate） |
| 見た目変更と導線変更の同時多発 | P1＝配置、色はトークン導入まで。P2＝ヘッダー |
| 印刷・色覚 | 画面色と印刷トークン分離／ラベル必須 |
