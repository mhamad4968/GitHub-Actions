## §1. 背景・目的

### 1.1 背景

- JRE-C_Hub のアカウントを **Excel**（`C-Hubアカウント一覧` シート）で管理している。
- 現在 **47 行 / 46 ユニーク ID**（2026-06-27 時点）。
- 昨日完成した **JREクラウドアカウント台帳（744/745）** と同様の運用を Space 34 に追加する。

### 1.2 目的

1. Excel 相当の台帳を kintone に置き、**日常操作はダッシュ**で行う。
2. **月次アカウント数量**を JRE745 **同型 UI** で集計（§5 — 小計/全社合計の数え方のみ差分）。
3. **権限**（署名者/承認者等）を **サブテーブル**で複数付与できるようにする。

### 1.3 スコープ外（v1）

| 項目 | 理由 |
|------|------|
| C-Hub 側 API 自動同期 | v1 は手動運用 |
| 595 `dept_name` の自動反映 | C-Hub **部署** は 595 と別体系 |
| 月次確定スナップショット | v1 は都度再計算 |
| 権限別**集計**軸 | v1 は一覧**フィルタ**のみ（§8）。集計表の権限軸は v1.1 候補 |

## §4. レコードモデル

### 4.1 通常（1人1拠点）

- **1 レコード** = 1 ID × 1 所属グループ × 1 部門
- **権限サブテーブル**に 1 行以上（複数権限可）
- 権限に `署名代行者` を含む場合、**署名代行対象サブテーブル**に 1 行以上（複数対象可）

### 4.2 イレギュラー（複数拠点 — 浜田確定）

| 項目 | 内容 |
|------|------|
| **持ち方** | **拠点ごと別レコード**（同一 ID / メール可） |
| **UI** | 一覧・詳細で **赤字バナー**「同一 ID が複数拠点に登録（イレギュラー）」 |
| **新規** | 同一 ID が既存なら **確認ダイアログ** → 登録可 |
| **整理** | 例: 諸治さん `kensetu_tosou203` の関越行は **削除予定**（移行後に整理） |

### 4.3 ライフサイクル

JRE745 同型（新規 / 編集 / 利用終了（退職）ボタン / 物理削除なし）に加え、終了済みレコードは一覧・編集画面の **利用再開** から確認後に `end_date` を空へ戻す。更新は現在 revision を指定し、kintone レコード履歴を監査証跡とする。

## §5. 月次集計（JRE745 同型 + 差分）

### 5.1 稼働判定（JRE745 同型）

```
カウント対象レコード =
  利用開始日 ≦ 月末 M
  かつ（利用終了日が空 または 利用終了日 > M）
```

### 5.2 レイアウト（JRE745 同型）

- **行**: 部門（§7.5）
- **拠点小計**: 所属グループごと
- **最終行**: 全社合計
- **列**: 指定期間内の各月（YYYY-MM）
- **絞込**: 期間・所属グループ・部門 **チップ toggle**（745 同型）。**条件クリア**で当年通年・全チップ ON
- **出力**: xlsx / 印刷（JRE745 同型）

### 5.3 カウント方式（浜田確定 — JRE745 との差分）

| 行種別 | 数え方 |
|--------|--------|
| **部署行** | **レコード数**（active かつ org+dept 一致） |
| **拠点小計** | **レコード数**（active かつ org 一致・選択部署内） |
| **全社合計** | **ID（user_id）ユニーク数** — 同一 ID の複数拠点レコードは **1 カウント** |

**例**: 同一 ID が東北・関越の 2 レコード → 各小計 +1、**全社合計 +1**（小計合計 2、全社 1 になり得る）

### 5.4 集計表下の備考（浜田確定 — 2026-06-27）

集計アコーディオン内、**表の直下**に以下を置く。

#### 5.4.1 固定注記（常時表示・折りたたみ可）

```
【集計の見方】
・拠点小計・部署行は「レコード数」です。
・全社合計は「ID（ログインID）のユニーク数」です。
・同一 ID が複数拠点にある場合、小計の合算が全社合計より大きくなることがあります（イレギュラー）。
・現在、アカウント棚卸が未完了のため一時的に重複が残っている場合があります。整理後は全社合計と整合します。
```

#### 5.4.2 重複 ID 自動備考（浜田確定 — 2026-06-27 改）

| 項目 | 内容 |
|------|------|
| **UI** | 表の下に **自動生成テキスト**（担当者の手入力欄は **v1 では設けない**） |
| **トリガー** | 集計対象期間・絞込内に **同一 `user_id` が 2 レコード以上** active な月がある |
| **自動記載例** | 「※ 同一 ID の複数拠点登録: `kensetu_tosou203`（諸治　友一郎）— 東北支店・関越支店（全社合計は ID ユニークのため小計合算と一致しない場合あり）」 |
| **0 件時** | 重複ブロックは **非表示**（固定注記 §5.4.1 のみ） |
| **xlsx/印刷** | 固定注記 + 自動備考（重複がある場合のみ）を表下に含める |

**実装**: 集計再計算時に `user_id` ごとに active レコードをグループ化 → 2 件以上の ID を列挙して HTML / xlsx 脚注へ出力。

## §7. フィールド定義（DB）

### 7.1 レコード本体

| # | ラベル | code | 型 | 必須 | 備考 |
|---|--------|------|-----|------|------|
| 1 | ID | `user_id` | 文字列（1行） | ○ | **自由入力**。新規後変更不可。**グローバル unique 禁止**（複数拠点イレギュラー可） |
| 2 | アカウント名 | `user_name` | 文字列（1行） | ○ | |
| 3 | 所属グループ | `org` | ドロップダウン | ○ | §7.4 |
| 4 | 部門 | `dept` | ドロップダウン | ○ | §7.5 |
| 5 | メールアドレス | `mail` | 文字列（1行） | ○ | |
| 6 | 利用開始日 | `start_date` | 日付 | ○ | 移行時既定=移行日 |
| 7 | 利用終了日 | `end_date` | 日付 | — | 空=稼働中 |
| 8 | 備考 | `note` | 文字列（複数行） | — | |

### 7.2 権限サブテーブル `permissions`

| 列 | code | 型 | 必須 |
|----|------|-----|------|
| 権限 | `perm` | ドロップダウン | ○ |

**同一レコード内**で同一 `perm` の重複行は **警告**（保存可 / 要確認）。

### 7.3 署名代行対象サブテーブル `proxy_targets`

| 列 | code | 型 | 必須 |
|----|------|-----|------|
| 社員名 | `proxy_name` | 文字列（1行） | ○ |
| メールアドレス | `proxy_mail` | 文字列（1行） | ○ |

- App 595 の社員検索モーダルから複数名を追加し、選択済み行から個別削除できる。
- メールアドレスの trim + 小文字化（メールなしの場合は氏名）で重複を拒否する。
- アカウント本人と同じメールアドレスは対象にできない。
- `署名代行者` 権限がある場合のみ 1 名以上必須。権限がない状態で対象が残っている場合も保存を拒否する。
- 既存 48 レコードは移行・更新しない。必要なレコードだけ通常の編集操作で設定する。

### 7.4 所属グループ（5 種）

正本: `scripts/data/jre-chub-account-orgs.json`

本社 / 東京支店 / 東北支店 / 関越支店 / 湾岸工事所

### 7.5 部門（13 種）

正本: `scripts/data/jre-chub-account-depts.json`

`－` / 仙台営業所 / 千葉営業所 / 新潟営業所 / 東京リペア部 / 東京施工部 / 水戸営業所 / 盛岡営業所 / 秋田営業所 / 長野営業所 / 関越施行部 / 高崎営業所 / 湾岸工事所

### 7.6 権限（5 種）

正本: `scripts/data/jre-chub-account-perms.json`

グループ管理者 / 承認者 / 署名代行者 / 署名者 / 閲覧者

### 7.7 595 連携（JRE745 同型 — 浜田確定）

| 項目 | 595 から |
|------|----------|
| アカウント名 | ○ `user_name` |
| メール | ○ `mail` |
| 所属グループ | △ `group_name` → マッピング（`scripts/data/jre-chub-account-group595-to-org.json`）。未マッチ手選 |
| **ID** | **× 手入力**（595 に無い） |
| 部門 | **× 手選**（C-Hub 専用マスタ） |
| 権限 | **× 手選**（サブテーブル） |
| 署名代行対象 | ○ `user_name` + `mail`（複数検索・選択） |

### 7.8 バリデーション

- `mail`: `@` を含む形式推奨（JRE ほど `@j-bis.co.jp` 固定 **しない**）
- `user_id`: 空禁止・**形式自由**
- `end_date >= start_date`
- 同一 ID 既存時: **警告**（イレギュラー登録）
- `署名代行者` 権限あり: 署名代行対象 1 名以上必須
- `署名代行者` 権限なし: 署名代行対象は空であること
- 署名代行対象: メール基準（fallback 氏名）の重複禁止・本人メール禁止

### 7.9 一覧検索

JRE745 §7.6 同型（haystack + AND トークン）。対象に `permissions` 結合文字列と署名代行対象の氏名・メールを含める。

## §8. ダッシュ UI

| 機能 | 内容 |
|------|------|
| **一覧** | Excel 風。複数拠点同一 ID は **赤字マーク**。`代行対象` 列は氏名を結合表示し、tooltip に氏名・メールを表示 |
| **検索・クリア** | キーワード AND 検索（§7.8）。**クリア** → 検索空・表示 **稼働中**・権限 **すべて** |

| **権限表示** | 1 件=そのまま / 2 件=両方表示 / 3 件以上=先頭＋「他複数権限あり」（tooltip で全件）。Excel/印刷は全件 |
| **新規・編集** | 595 検索（**クリア**付き）+ ID 手入力 + 権限サブテーブル + 署名代行対象の App 595 複数検索 |

| **出力** | 一覧 / 集計 xlsx・印刷 |
