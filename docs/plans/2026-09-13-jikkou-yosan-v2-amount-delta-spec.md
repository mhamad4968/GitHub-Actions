# 756 金額増減（直前版との差）

> **日付**: 2026-09-13  
> **状態**: **実装 GO**（浜田・同日チャット）  
> **親**: `docs/plans/2026-07-19-jikkou-yosan-ver02-redesign-spec-draft.md`  
> **対象**: App **756 画面のみ**。kintone 増減フィールドは作らない。757/758 スキーマ・**736 不触**・**757 customize 不触**・**予実 G0 不触**・帳票 v1 非対象。

## 合意（チャット 2026-09-13）

版を重ねたとき、**現行の金額が直前版からいくら動いたか**を画面で見せる。比較の概念は版管理の「直前／当初／選択」に寄せるが、**v1 は直前版だけ**。736 のコードはコピーしない。

| 項目 | 決め |
|------|------|
| 列位置 | **金額の直後**。内訳は備考の前。請負は消化率（÷①）の前 |
| 出す表 | 請負・給与・原価投影・内訳明細／諸経費・計・①⑧⑨／施工・保安計 |
| 出さない | 予実タブ、帳票 v1、第1版 |
| 比較対象 v1 | `source_record_id` の **直前版のみ**（当初／選択は後続） |
| 突合 | `rowKey`。内訳は `stableBlockId` × `rowKey`。費目名・契約工種名では突合しない |
| 保存 | 計算は表示専用。備考へ自動書き込み **禁止**（次版コピーで備考は従来どおり複写） |

## 列の表示／非表示

- 第1版、または `source_record_id` が空／自己参照／読込失敗: **列ごと出さない**（セルを「－」で埋めない）。
- 2版以降で直前版が取れたときだけ列を出す。

## 行の表示

| 状態 | 表示 | ホバー |
|------|------|--------|
| 前版に同じキーが無い（新規行） | **－** | 前版に無い行 |
| 金額が同じ（差 0。数量・単価だけ変わっても金額差 0 ならこちら） | **－** | 変化なし |
| 金額が違う | 符号付き円（`+48,000` / `-12,000`） | 金額・数量・単価の前後 |

変更時は **同じセルの数字の下** にラベル（計・諸経費・①⑧⑨はラベルなし）:

- 単価だけ違う → `単価変更`
- 数量だけ → `数量変更`
- 両方 → `数量・単価`

削除行は現行表に出ないので増減セルも出さない。**計・①⑧⑨は現行合計 − 前版合計**（新規の足し込みと削除の落ち込みを含む）。そのため **明細の「－」を足しても計の増減と一致しない**のは仕様。

## 計算と読込

- 詳細画面を開いたとき **直前版を 1 回だけ**読む（App1 は版一覧の `$id` 優先。無ければ `GET /k/v1/records.json`。App2 は既存 `fetchExistingDetailRows`）。行ごとの REST 禁止。
- 取れた前版は **不変スナップショット**。現行はメモリ上の請負／給与／内訳から再計算するので、下書き編集中も増減が追従する。
- 数量・単価の同値判定は `decimal.compare`（文字列小数。カンマ除去）。
- 金額差は整数円（既存 `displayInteger`／画面のカンマ表示と同じ）。

## 非対象（v1）

- 当初版・任意版の切替 UI
- 増減率％、前版金額の別列
- 削除行の折りたたみ表示（736 同型）
- 印刷（`jy2-pr-*`）
- 予実（G0 実装 GO 待ちのまま）

## 受け入れ

1. 第1版: 金額増減列が無い。
2. 2版: 列が出る。新規行は「－」。金額不変は「－」。単価だけ変えると数字＋`単価変更`。
3. 内訳の計と明細の「－」が一致しなくてもよい。
4. 備考が自動で変わらない。
5. 736 / 757 customize / 予実タブは無変更。
