## 4. 提案申請（新①）— UI・WF

### 4.1 申請画面（Q-UI / Q-UX / Q58）

**上段（常時）**: 部署名 → 代表提案者（社員検索）→ 提案種別 → 全幅で提案件名  
**提案日**: 初回申請時自動。手入力なし  
**下段**: アコーディオン5ブロック（目的→現状→問題点→改善案→効果）＋添付  
**提案者一覧**: 所属＋社員名（全員・代表と1行目双方向連動）— **年次付与の正本**

**UX**:
- 上段3完了→目的自動展開、ブロック完了で次を連鎖（Q-UX-01/02）
- 未入力は橙バッジ・「次へ」で進まない（Q58）
- テーマ: **薄青グラデ**（Q60）

### 4.2 評価画面（Q53–56 / Q-UX）

- **≥1280px**: 2ペイン（左=要約+アコーディオン、右=評価UI sticky）
- **&lt;1280px**: 縦積み（上=評価、下=要約）
- テーマ: **薄茶グラデ**
- 評価=**ドロップダウン**（ルックアップ「取得」廃止）
- 差戻し=モーダル・理由必須（Q-UX-04）
- 承認=評価完了後・確認モーダル（Q-UX-05/06/07）
- **支店長判断ON**（部長のみ）→ 部長未評価でも支店長へ（Q-UX-06）

### 4.3 差戻し・再申請（Q-WF-05 / Q-UX-08〜11）

| 項目 | ルール |
|------|--------|
| 差戻し | 申請内容の**やり直し**。部長・支店長・人事が可。理由**必須** |
| 再申請後 | WFは**部長評価から再開**。提案日は**初回のまま** |
| 申請者UI | 修正待ち→上部アラート（差戻し理由）＋ボタン「再申請する」 |
| 一覧 | 橙バッジ「差戻し・要修正」・要修正を最上段 |
| 履歴 | 新①内サブテーブル2種。**削除・無効化なし**（Q-HIST-02/03） |

### 4.4 評価制度（変更不可）

- 3軸（効果・工夫度・努力度）各5段＋アイデア総合5 = **20段階**
- 合計点→自動ランク（A≥18 / B14–17 / C≤13）→ 評価者が**表彰ランク（最終）**を確定（Q63/Q70）
- 付与ポイント: A=5000 / B=1000 / C=100（Q-ANN-01）
- 複数提案者: **按分なし・全員に全額**（Q-ANN-02）
