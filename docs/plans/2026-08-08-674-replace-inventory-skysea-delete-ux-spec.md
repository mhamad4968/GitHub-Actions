## 1. PC買替（B）

### 1.1 実行前確認（2段・はい／いいえ）

「PC買替」押下後、現行の1回 confirm をやめ、次の順で出す（いずれも **いいえ＝手続き中止・レコード変更なし**）。

1. `旧PC「{pc_name}」は廃棄になります。よろしいですか？`
2. `買替後PCへアカウント情報を引き継ぎます。よろしいですか？`

旧PC名は必ず表示する。

### 1.2 備考自動追記（新旧両方）

買替成功時のみ:

- **旧PC**  
  `[PC買替 yyyy-mm-dd] 本PCを廃棄に変更。新レコード番号: {newId}`
- **新PC**  
  `[PC買替 yyyy-mm-dd] 旧PC「{oldPcName}」を廃棄に変更（旧レコード番号: {oldId}）`

既存備考がある場合は改行追記。中止時は書かない。

### 1.3 買替後案内（B2）

新レコード遷移後のバナー／案内に含める:

- PCを切り替えたので **端末情報の入力を忘れない**こと
- **赤字**: 旧PCの SKYSEA クライアント削除が必要。室長へ手順を確認し必ず実施すること
- 旧PCは SKYSEA 削除対応リスト（admin）で完了すること

### 1.4 新レコード初回保存ゲート

`import_source` が `PC_REPLACE_FROM_674` で始まるレコードの **最初の保存のみ**:

- confirm: `端末情報は入力しましたか？`
- **はい** → 保存継続
- **いいえ** → 保存中止。`必ず端末情報を入れてください。入力後に保存できます。`

2回目以降の保存では出さない（session／フラグで判定可。実装は `sessionStorage` または保存成功後に内部メモ）。

一覧からの買替対象探しやすさ改善は **見送り**。

## 2. 棚卸（C）

### 2.1 対象

| 軸 | 含む | 除外 |
|----|------|------|
| ステータス | 利用中・保管 | 廃棄・取消 |
| 種別 | 個人・共有・JR端末 | **サーバーNAS・その他** |

- 一括棚卸の一覧取得・個別棚卸ボタン・未棚卸一覧は上記に従う。
- NAS／その他では棚卸 UI を **非表示**。

### 2.2 空履歴行の禁止

`inventory_history` へ追記するとき:

- 棚卸日または棚卸者が空なら **行を追加しない**（エラー表示）
- PUT 前に、日付・者・方法がすべて空の行は **送らない／除去する**

### 2.3 棚卸状況一覧（C1）

- **配置**: 「いまの条件」行の直下
- **UI**: アコーディオン「棚卸状況一覧」・**初期閉じ**
- **期間**: 毎年 **5月1日〜翌4月30日**（今期）。670 の期間キーがあれば整合を優先し、無ければこの規則で算出
- **月次集計なし**
- **行**: 747集計表イメージの **グループ×部署**（浜田提示マスタ順。東海支店・リフォーム統括・鉄構支店含む）
- **列**: グループ／部署／棚卸済／棚卸未了
- **未了クリック** → 当該グループ×部署の未了一覧へ
- マッチは主に `dept_name`。未一致は末尾「未分類」
- 完了定義: 今期内に `latest_inventory_date` あり

### 2.4 一括棚卸（C2）

- 対象クエリに **種別 in (個人, 共有, JR端末)** を必須化
- 棚卸者は **手入力**（自動入力はしない。既存「ログイン名を共通欄へ」は残してよい）
- 必須空欄バックフィル（`skysea_manual_done` 等）は継続

### 2.5 未棚卸一覧（C3）

- 「個別棚卸へ」「一括棚卸へ」ボタンを用意
- **個別**: 当該レコード詳細を開く（個別棚卸は詳細から）
- **一括**: 一括棚卸モーダルを開く（可能なら所属を引き継ぐ）

### 2.6 個別棚卸 UI（C4）

画面簡略化は **見送り**。空行バグ修正のみ。

## 3. SKYSEA クライアント削除（個人・廃棄／買替）

### 3.1 フィールド（674・新規）

| code | 型 | 内容 |
|------|-----|------|
| `skysea_client_delete_status` | DROP_DOWN | `未了` / `完了`（空＝対象外または未設定） |
| `skysea_client_delete_date` | DATE | 完了日（完了時にセット可） |

配置: `skysea_system_meta` グループ内（既存手動フィールド近傍）。  
表示: 既存 SKYSEA グループと同じく **admin ∧ 個人** を基本（リスト完了が正のため、詳細は表示／補助）。

### 3.2 自動付与

次のとき、**種別＝個人**かつ旧／対象レコードを廃棄にする処理で:

- `skysea_client_delete_status` が空または未了でない完了以外 → **`未了` をセット**（既に完了なら触らない）

対象イベント:

- PC買替で旧を廃棄
- 転用廃棄など「廃棄」にする既存フロー（個人）

共有／JR／NAS／その他は付与しない。

### 3.3 admin TOP 警告

一覧（index）で LoginID=`admin` のとき:

- `skysea_client_delete_status = "未了"` が1件以上あれば  
  「SKYSEAアカウント削除しなければいけない対象が残っています（N件）」を表示
- クリックで削除対応リストを開く

### 3.4 専用リスト（完了の正）

- ボタン例: 「SKYSEAクライアント削除対応リスト」（admin）
- 未了一覧（個人・未了）
- 行で **完了チェック／完了ボタン** → status=`完了`、date=今日（実装）
- 詳細画面の手編集は補助（正はリスト）
