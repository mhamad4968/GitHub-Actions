## §1. 概要・目的

### 1.1 背景
- 部署メンバーから「PC 台帳とアカウント台帳が分かれてて使いづらい」要望
- 既存 594 (PC管理台帳ver.2) + 627 (アカウント管理台帳) の 2 アプリ運用が複雑
- 4/19-21 で M365 ライセンス管理 (5 台/アカウント) の運用課題が顕在化

### 1.2 目的
1. **1 PC = 1 アカウント** の単純な構造で「1 画面完結」を実現
2. M365 5 台ライセンス制限の **マスタによる厳守管理**
3. 旧アプリは **保険として 1 か月残置**（参照のみ・書込ロック）

### 1.3 設計方針
- **既存破壊ゼロ**: 旧 594/627 は完全無傷で残す（他アプリ参照影響ゼロ）
- **新規アプリ並行運用**: 新・PC台帳ver.1 を新規構築
- **段階移行**: 試運用 → 本番切替 → 旧アプリ書込ロック

### 4.10 リレーション運用ルール

#### 4.10.1 個人 PC = 1 ユーザー最大 2 台
- 社内規定として **必須実装**（会社用 + 持ち出し用）
- 3 台目を紐付けようとすると保存時にエラー
- 既存 594 の同等機能から移植

#### 4.10.2 共有アカウント = PC 単位重複登録
- 1 共有 M365 ID を 5 PC で使う場合 → 5 PC レコードに同じ m365_id を持つ
- M365管理マスタの `usage_count` で 5 台上限を厳守

#### 4.10.3 PC 買替時
- 古い PC = 自動で「廃棄」へ
- 古い PC のアカウント情報を新 PC に **引き継ぎ**（M365 ID も同じ ID を継続）
- M365管理マスタの `usage_count` は変動なし、`linked_pcs` の PC 名のみ更新

#### 4.10.4 PC 廃棄/削除時の M365 解放
- ステータス変更「廃棄」 or レコード削除イベントで自動発火
- 紐付き m365_id を取得 → M365管理マスタの該当レコードの `usage_count` を -1
- `linked_pcs` から該当 PC 名を削除
- `status = 満杯` だった場合 → `利用可` に自動戻し

#### 4.10.5 部署異動時
- アカウント情報はそのまま継続（個人に紐付くため変更不要）
- 595 社員マスタ更新で所属名・所属グループが自動反映

## §5. M365管理マスタ — 詳細仕様

### 5.1 用途
- 共有/JR 用 M365 ID の **5 台ライセンス厳守管理**
- 払い出し・解放を新・PC台帳ver.1 から自動制御
- 個人 M365 ID は管理対象外（別ロジックで自動生成）

### 5.2 フィールド設計（10 個）

| code | type | 内容 |
|---|---|---|
| `m365_id` | SINGLE_LINE_TEXT (UNIQUE) | M365 ID（jbs****@…onmicrosoft.com）|
| `m365_pw` | SINGLE_LINE_TEXT | `kent2511K#`（環境設定マスタから取得）|
| `account_type` | DROP_DOWN | 種別（共有 / 個人）|
| `status` | DROP_DOWN | 利用可 / 満杯（5/5）/ 廃止 |
| `serial_no` | NUMBER | 連番（jbs**0001** = 1）|
| `usage_count` | NUMBER (0-5) | 使用ライセンス数（自動更新）|
| `linked_pcs` | MULTI_LINE_TEXT | 使用中 PC 名一覧（カンマ区切り）|
| `created_at` | DATETIME | 作成日時 |
| `disabled_at` | DATETIME | 廃止日時 |
| `note` | MULTI_LINE_TEXT | 備考 |

### 5.3 自動割当ロジック

```javascript
1. 新・PC台帳ver.1 で「共有用 自動生成」ボタン押下
2. M365管理マスタを query:
   query: status = "利用可" AND usage_count < 5 ORDER BY serial_no ASC LIMIT 1
3. 該当 0 件:
   - システムが次連番のレコードを自動作成 (jbs<次番号>)
   - alert「Microsoft 365 管理画面で <m365_id> を作成してください」
   - そのレコードを使って次のステップへ
4. 該当 1 件取得 → PC レコードに m365_id, m365_pw 書き込み
5. M365管理マスタ側:
   - usage_count を +1
   - linked_pcs に PC 名を追記
   - usage_count = 5 になったら status を「満杯」に自動切替
6. PC レコード保存
```

### 5.4 解放ロジック（PC 廃棄/削除時）

```javascript
1. PC ステータスを「廃棄」に変更 or レコード削除
2. 紐付き m365_id を取得
3. M365管理マスタの該当レコード:
   - usage_count を -1
   - linked_pcs から該当 PC 名を削除
   - status「満杯」 → 「利用可」自動戻し
```

### 5.5 整合性保証（TSB-008 教訓）
- `usage_count` は **CALC ではなく NUMBER + JS 自動更新**（CALC SUM の罠回避）
- **月次リコンサイル スクリプト**: 全 M365 ID について新・PC台帳ver.1 で実際に何台使われてるか再計算 → ズレ修正
- **監査ログ**: 割当・解放を `logs/m365-allocation.log` に記録

### 5.6 ビュー
- 標準: 全件・serial_no 昇順
- ⚠ 満杯一覧: filterCond=`status = "満杯"`
- 📊 使用率順: ORDER BY usage_count DESC

### 5.7 初期データ
- **私が CSV を準備**（既存 627 の共有 M365 ID を抽出 → マスタ初期登録）
- 浜田が新・PC台帳ver.1 に CSV 取り込みする際、整合性が取れる初期状態を保証
