## §1. 背景・目的

### 1.1 背景

- USB メモリ・外付けドライブ・光学ディスク・SD カード、および **カメラ等の想定外 IT 資産**を、所属単位で台帳管理する必要がある。
- 識別子（シリアル・製造番号・社内管理番号等）は **媒体・機器ごとにバラバラ**で、固定フィールド 1 本では運用できない。
- **各所属のシステム担当**が担当範囲を登録する（organization ドロップダウンは **持たない**）。

### 1.2 目的

1. **694 型 Excel 風ダッシュ**で、新規・修正・廃止・削除を日常操作できる台帳を置く。
2. **595 社員マスタ**と連携し、**1 物理媒体 / 1 機器 = 1 レコード**（利用者は **必ず 1 名**。同一 `emp_id` の **追加登録可** — 例: 同一社員の USB 複数本）を記録する。
3. **支店・営業所単位**および **社員単位**の一覧・リスト出力・印刷（ソフトウェア台帳 §9.5 同型）。

### 1.3 管理対象（v1）

| 区分 | `media_type` | 備考 |
|------|--------------|------|
| **A** | USBメモリ | |
| **B** | 外付けHDD/SSD | |
| **C** | 光学ディスク | DVD / Blu-ray 等 |
| **D** | SD/microSD | 単体媒体 |
| **F** | **その他** + `media_type_other` | カメラ・ビデオカメラ等。**種別名はテキスト入力** |

### 1.4 スコープ外（v1）

| 項目 | 理由 |
|------|------|
| **E テープ・バックアップ媒体** | 対象外（浜田確定） |
| **PC 台帳 674 との自動連携** | v1 は独立台帳 |
| **ソフトウェア台帳との同一レコード** | 別台帳。同一利用者が両方に行を持つことは可 |
| **在庫数・貸出返却ワークフロー** | 割当記録のみ |
| **`organization` 手入力** | `dept_name` / `group_name` + ダッシュ UI |

## §2. 用語

| 用語 | 意味 |
|------|------|
| **1 物理 = 1 レコード** | USB 1 本、SD 1 枚、HDD 1 台、カメラ 1 台 … **各 1 行**（**1 レコード = 1 割当・利用者 1 名**。同一社員 **複数レコード可**） |
| **識別スロット** | `id_kind_N` + `id_value_N`（最大 3 組・案 A） |
| **`media_type_other`** | `media_type=その他` のときの **自由記述種別**（例: カメラ） |
| **その他** | 用語 §1.3 の **F 区分**（カメラ等）。`media_type` ドロップダウン値とも同名 |

## §5. ステータスとライフサイクル

### 5.1 ステータス

| 値 | 意味 |
|----|------|
| **利用中** | 割当中・使用中 |
| **廃止** | 使用停止（返却・廃棄・紛失記録等。**レコード残す**） |

**既定値**: 新規 **`利用中`**。

### 5.2 操作

| 操作 | 内容 |
|------|------|
| **新規** | §7 必須 + 595 + 自動採番 |
| **修正** | `registered_date` 以外編集可 |
| **廃止** | `status=廃止`（**レコードは削除しない**） |
| **削除** | **誤登録**のみ REST DELETE |

### 5.3 廃止の不可逆（2026-06-14 浜田確定・案 A — ソフトウエア台帳 §5.3 同型）

| ルール | 内容 |
|--------|------|
| **廃止 → 利用中** | **不可**（**終端**）。UI に復帰操作は **持たない** |
| **再利用** | 廃止済みレコードを **別利用者・再割当に流用しない** |
| **再割当** | **新規登録**（新 `legacy_no`） |
| **退職者で廃止した行** | **再利用しない**（後任・同一媒体の再割当も **新規登録**） |
| **誤廃止** | **削除**（誤登録）または **新規登録**。`status` の戻しはしない |

**実装**: 廃止 PUT は **`利用中` → `廃止` のみ**。編集モーダルで `status` は **表示のみ**。

## §6. 595 社員マスタ連携

**参照**: [595 社員マスタ](https://jbis-kintone.cybozu.com/k/595/)（674 / ソフトウエア台帳同型）

### 6.1 方針

- **新規登録時に 595 から利用者を必ず 1 名選択**（**1 レコード = 1 物理媒体 / 1 機器・利用者 1 名**。同一 `emp_id` の **追加登録可** — 2026-06-14 浜田確認 #1）。
- **社員検索**（674 同型）で `emp_id` / `user_name` / `dept_name` / `group_name` を反映。

### 6.2 採用しない 595 項目（v1）

- `mail` / `mail_acct` — 本台帳では **不要**（突合キーは **`emp_id` 正**）。

### 6.3 バリデーション（2026-06-14 浜田確認 #3）

- 新規・修正保存時: **`user_name` 空** → エラー。
- **社員検索**: 検索クエリに **`employment_status not in ("退職")`** — 退職者は **一覧に出さず選択不可**（ソフトウエア台帳 §6.3 同型）。

### 6.4 退職者と台帳表示（2026-06-14 浜田確認 #3）

| 場面 | ルール |
|------|--------|
| **社員検索**（新規・修正） | 退職者は **出さない**（§6.3） |
| **ダッシュ**（メイン表・チップ・検索・リスト・社員印刷） | 割当 **`emp_id` が 595 上で退職** の行は **一切表示しない**（`status=利用中` のままでも非表示） |
| **データアプリ（DB 標準 UI）** | 閲覧のみ。退職者行も **レコードとして残る** |
| **正式停止** | 退職に伴う停止は **`status=廃止`**。v1 では **595 退職イベントの自動 PUT はしない**（表示除外のみ。必要なら担当者が **手動廃止**） |

### 6.5 支店・営業所の見方

ソフトウエア台帳 **§6.5 と同一**（`dept_name` / `group_name` + 所属チップ・リスト一覧）。

### 6.6 所属・氏名の自動反映（595 保存連動 — 2026-06-14 浜田確認 #3）

ソフトウエア台帳 **§6.6 同型**（`customize/595/desktop.js` に **`syncStorageMediaLedgerMirrorFrom595`** を新設。`emp_id` 突合・**`status=利用中` のみ**・`user_name` / `dept_name` / `group_name` を bulk PUT）。

## §8. 識別スロット（案 A — 確定 2026-06-13）

### 8.1 `id_kind` の選択肢（媒体向け 5 択）

| 値 | 用途 |
|----|------|
| **シリアル番号** | 媒体・機器の S/N |
| **製造番号** | 工場番号・個体番号 |
| **管理番号** | 社内管理ラベル（S/N 無し時） |
| **型番** | 型番・品番（識別として持つ場合） |
| **その他** | 上記に当てはまらない識別子 |

> ソフトウェア台帳の「プロダクトID」「アカウントID」に相当するものは、媒体台帳では **管理番号 / その他** で吸収。

### 8.2 スロット構成

| スロット | 必須 | ルール |
|----------|------|--------|
| **1** | ○ | 新規時 **種別・値両方必須** |
| **2・3** | — | **セット**で入力（片方のみ → エラー） |
| **4 個目以降** | — | **`note` に記載** |

同一レコード内で **同一 `id_kind` 重複** → **警告確認**（キャンセルで保存中止）。

### 8.3 他レコードとの識別値重複（2026-06-14 浜田確定・案 A）

保存直前、各スロット（`id_kind_N` + `id_value_N`、trim 後・空除外）について **他レコード**を REST 検索（編集時は自 `$id` 除外）。対象 status は **`利用中` / `廃止` 両方**。

- 同一種別＋同一値が **1 件でも**あれば **確認ダイアログ**:

  > **同一のハードウエア情報（シリアル等）が既に登録されています。登録しますか？**

- **OK** → 保存続行。**キャンセル** → 保存中止。
- **kintone フィールド unique は付けない**（JS のみ）。

**注**: 媒体台帳にソフトウエアの「ボリューム＝重複可」例外は **なし**（全 `media_type` で本チェック）。

### 8.4 一覧表示（計算列 — UI 表示名 **ハードウエア情報**）

`id_kind_N: id_value_N` を `/` 結合（空スロット除外）。DB フィールドは持たない（内部コード `id_kind_*` / `id_value_*`）。
