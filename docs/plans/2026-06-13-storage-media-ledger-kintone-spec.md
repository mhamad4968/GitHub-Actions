## §0. 進め方

1. **本書で項目・運用・フィールドを確定**する（**完了 — 2026-06-13**）。
2. **ソフトウェア管理台帳 v1** の目視・運用確認後、浜田 GO で **kintone アプリ作成**。
3. フィールド投入 → **ダッシュ customize** → 目視確認 → 各所属システム担当へ周知。

**技術方針**（ソフトウェア台帳・694 同型）:

| 構成 | 役割 |
|------|------|
| **データアプリ** | 1 媒体 / 1 機器 = 1 レコードの正本 |
| **ダッシュアプリ** | 日常の Excel 風 UI（JS + REST でデータアプリへ書込） |
| **有償プラグイン** | **NG** |
| **DB 標準 UI** | 保存・削除 **全面禁止**（693 型 customize） |

**コード方針**: customize は `customize/storage-media-ledger/` を新設。ソフトウェア台帳（`software-ledger`）と **UI パターンを共通化**するが、アプリ ID・フィールドコードは **別管理**。

## §1. 背景・目的

### 1.1 背景

- USB メモリ・外付けドライブ・光学ディスク・SD カード、および **カメラ等の想定外 IT 資産**を、所属単位で台帳管理する必要がある。
- 識別子（シリアル・製造番号・社内管理番号等）は **媒体・機器ごとにバラバラ**で、固定フィールド 1 本では運用できない。
- **各所属のシステム担当**が担当範囲を登録する（organization ドロップダウンは **持たない**）。

### 1.2 目的

1. **694 型 Excel 風ダッシュ**で、新規・修正・廃止・削除を日常操作できる台帳を置く。
2. **595 社員マスタ**と連携し、**1 物理媒体 / 1 機器 = 1 レコード**、**利用者 1 名**を記録する。
3. **支店・営業所単位**および **社員単位**の一覧・リスト出力・印刷（ソフトウェア台帳 §9.5 同型）。

### 1.3 管理対象（v1）

| 区分 | `media_type` | 備考 |
|------|--------------|------|
| **A** | USBメモリ | |
| **B** | 外付けHDD/SSD | |
| **C** | 光学ディスク | DVD / Blu-ray 等 |
| **D** | SD/microSD | 単体媒体 |
| **F** | **その他** + `media_type_other` | カメラ・ビデオカメラ等。**種別名はテキスト入力** |

### 1.4 スコープ外（v1）

| 項目 | 理由 |
|------|------|
| **E テープ・バックアップ媒体** | 対象外（浜田確定） |
| **PC 台帳 674 との自動連携** | v1 は独立台帳 |
| **ソフトウェア台帳との同一レコード** | 別台帳。同一利用者が両方に行を持つことは可 |
| **在庫数・貸出返却ワークフロー** | 割当記録のみ |
| **`organization` 手入力** | `dept_name` / `group_name` + ダッシュ UI |

## §2. 用語

| 用語 | 意味 |
|------|------|
| **1 物理 = 1 レコード** | USB 1 本、SD 1 枚、HDD 1 台、カメラ 1 台 … 各 1 行 |
| **識別スロット** | `id_kind_N` + `id_value_N`（最大 3 組・案 A） |
| **`media_type_other`** | `media_type=その他` のときの **自由記述種別**（例: カメラ） |
| **その他** | 用語 §1.3 の **F 区分**（カメラ等）。`media_type` ドロップダウン値とも同名 |

### 7.2 ドロップダウン `media_type`

| 値 | 対象区分 |
|----|----------|
| USBメモリ | A |
| 外付けHDD/SSD | B |
| 光学ディスク | C |
| SD/microSD | D |
| **その他** | F → **`media_type_other` 必須** |

**一覧・帳票の種別表示**:

- 固定 4 種: `media_type` のラベルをそのまま表示。
- その他: **`その他（{media_type_other}）`** — 例: `その他（カメラ）`。

### 7.3 新規登録時の必須まとめ

| 必須 | 項目 |
|------|------|
| ○ | `media_type`、識別スロット 1、595 利用者 |
| 条件 | `media_type=その他` → `media_type_other` |
| 自動 | `legacy_no`、`registered_date`、`status=利用中` |
| 任意 | `item_name`、`capacity`、`purchase_date`（初期=登録日）、識別 2・3、`note` |

## §8. 識別スロット（案 A — 確定 2026-06-13）

### 8.1 `id_kind` の選択肢（媒体向け 5 択）

| 値 | 用途 |
|----|------|
| **シリアル番号** | 媒体・機器の S/N |
| **製造番号** | 工場番号・個体番号 |
| **管理番号** | 社内管理ラベル（S/N 無し時） |
| **型番** | 型番・品番（識別として持つ場合） |
| **その他** | 上記に当てはまらない識別子 |

> ソフトウェア台帳の「プロダクトID」「アカウントID」に相当するものは、媒体台帳では **管理番号 / その他** で吸収。

### 8.2〜8.4

スロット構成・バリデーション・一覧 **識別** 列の結合表示 — ソフトウェア台帳 **§8.2〜8.4 と同一**（フィールドコードも同じ `id_kind_*` / `id_value_*`）。

## §9. ダッシュアプリ — UI 要件

### 9.1 画面構成

ソフトウェア台帳 **§9.1 と同一**（所属チップ・リスト一覧作成含む）。

**検索対象**: 種別（表示名）・名称・容量・識別値・氏名・所属名・所属グループ。

### 9.2 表の列（左→右）

`legacy_no` | `status` | `registered_date` | `purchase_date` | **種別** | `item_name` | `capacity` | **識別** | `emp_id` | `user_name` | `dept_name` | `group_name` | 操作

### 9.3 モーダル

| モーダル | 項目 |
|----------|------|
| **新規** | 媒体種別（その他時テキスト表示）・名称・容量・識別（最大 3）・595・購入日・備考 |
| **編集** | 上記 + 登録日表示のみ |
| **廃止 / 削除** | ソフトウェア台帳同型（確認に **種別・名称・氏名** 表示） |

**媒体種別 UI**:

1. `media_type` ドロップダウン（5 値）。
2. **`その他` 選択時のみ** `media_type_other` テキストを表示（必須）。
3. 固定 4 種選択時は `media_type_other` を **空で保存**。

### 9.4 印刷

- メイン表: v1 **未実装**。
- **リスト一覧作成**からの印刷: **v1 実装**（674 / ソフトウェア台帳 §9.5 同型）。

### 9.5 支店・営業所・社員単位のリスト化

ソフトウェア台帳 **§9.5 全文と同一 UX**（利用者チップ・氏名列クリック・595 社員選択・§9.5.4 社員単位印刷を含む）。

リストモーダルの **媒体台帳固有**条件:

| 入力 | 検索フィールド |
|------|----------------|
| **媒体種別** | `media_type`（完全一致 or 部分一致）— 実装時 **`その他` は `media_type_other` も検索** |
| **名称** | `item_name` 部分一致 |

**結果表の列**:

`legacy_no` | `status` | **種別** | `item_name` | `capacity` | **識別** | `emp_id` | `user_name` | `dept_name` | `group_name` | `purchase_date`

**社員単位印刷の帳票ヘッダ**（§9.5.4 相当）:

```
記憶媒体等管理台帳 — 社員別一覧
氏名: {user_name}    社員番号: {emp_id}    所属: {dept_name} / {group_name}
出力日: {今日 JST}    件数: {n}件    ステータス: {選択条件}
```

**社員指定時のソート**: `media_type` 昇順 → `item_name` 昇順 → `legacy_no` 昇順。
