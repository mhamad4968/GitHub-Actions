## §1. 背景・目的

### 1.1 背景

- 社内各拠点の **複合機（MFP）** 情報を **Excel 1 シート**で管理している。
- 接続情報・機械番号・リース契約等を当部署が保守し、**業者への情報提供**に使う。
- 日常の確認・更新は **当部署メンバー全員**が行う。

### 1.2 目的

1. Excel と同等の情報を kintone に置き、**日常操作は台帳**で行う。
2. **拠点別の業者向け一覧印刷**と **全体一覧印刷**・**xlsx 出力**をダッシュから行う。
3. 移行・目視 OK 後は **Excel 表を削除**し、kintone のみ正本とする。

### 1.3 スコープ外（v1）

| 項目 | 理由 |
|------|------|
| **Space 48 ポータル 712 へのリンク追加** | 浜田が手動で対応（§11 Q15） |
| **PC 台帳 674 / トータル NW 737 との自動連携** | v1 独立台帳 |
| **SNMP 監視・カウンター取得** | 台帳化のみ |
| **有償 kintone プラグイン** | 使用しない |

## §6. 拠点・並び順

### 6.1 拠点名の入力

- **R68 正本** `scripts/data/jbis-location-sort-master.json` の `location_name` から **ドロップダウン選択**。
- **680 所属候補マスタ**（App 680）にも同一名称を追加し、他アプリからも再利用可能にする。
- **追加エントリ**: `子会社（株）ブリッジニアプラス`（sort_no **33**・末尾ブロック）。

### 6.2 Excel → 拠点名マッピング（移行時）

| Excel 表記 | kintone 拠点名 |
|------------|----------------|
| 本店 | **本社** |
| 関越支店（１）（２） | 関越支店 |
| 東京支店（１）（２） | 東京支店 |
| 首都圏支店（１）（２）（３） | 首都圏支店 |
| 札幌支店（１）〜（８） | 札幌支店 |
| 株式会社ブリッジニアプラス | **子会社（株）ブリッジニアプラス** |
| その他 | そのまま（東北支店、仙台営業所、…） |

**同一拠点複数台**: `location_name` は同一。`model_name` / `machine_no` / `note`（例: ブリッジニアプラス本社・鎌ヶ谷事務所）で区別。

### 6.3 sort_no（デフォルト並び）

1. **R68 拠点順**（本社 11 → … → 湾岸工事所 32）に従いブロック化。
2. **同一拠点内**は Excel 行順を維持。
3. **子会社（株）ブリッジニアプラス** 3 台は **sort_no 最大ブロック（34–36）** で一覧最下部。

並び正本の詳細は移行スクリプト内 `MIGRATION_ROWS`（36 件）に固定定義する。

### 6.4 未設定値（Q21）

Excel の `---` / `不明` は **そのまま保存・表示**（空欄にしない）。
