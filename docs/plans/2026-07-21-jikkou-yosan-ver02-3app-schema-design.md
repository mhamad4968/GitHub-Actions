| キー | 形式（案） | 発行タイミング | 保存先 |

## 3. アプリ① 実行予算書作成支援ツールver02

### 3.1 レコード＝1予算版（736と同型）

版ごとに別レコード。版メタは736流用（A-04）: `version_type`(必須DD5択)・`version_seq`・`source_record_id`・`revision_note`(任意)・`status`(下書き/版確定)・`is_locked`。

### 3.2 フィールド群

| 群 | 主フィールド | 備考 |
|---|---|---|
| システムキー | `project_id`・`project_business_key`・`budget_version_id`・`version_record_key` | 非表示。P-29の1系列検索は業務キー、JOINは不変`project_id`、同時作成競合は一意`version_record_key`で防止 |
| 工事基本情報 | 736ベース（発注者・工事コード[必須]・枝番・名称類・着手日・竣工日・現場入場・立案日・桁種別・発注支社・部門・安衛則88条[必須・既定「有」]・担当者・備考） | 工期日数＝`竣工-着手` 自動（D-34） |
| 請負明細 | サブテーブル `contract_lines`（施工帯／保安帯）: 契約工種・単位DD・数量・単価・金額税抜（**ROUNDなし積**＝X2/P-22）・備考 | ①=施工計+保安計 |
| 給与手当 | サブテーブル `salary_lines`: 役職名称・単位(初期`箇月`)・数量・単価・金額税抜・備考。消費税・税込は`－` | 総括直入力・内訳なし（D-30） |
| 総括原価行（投影） | サブテーブル `summary_cost_lines`: `stable_block_id`・内訳№・費用区分(施工/保安)・工種番号・システム入力工種・種別(手入力・総括限定)・単位・数量・単価・金額税抜（**②ブロック「計」の再生成可能キャッシュ・編集不可**＝P-21/P-33）・消費税率・税込併記・計算基準・備考 | **計算権威は②のみ**。①金額は表示用キャッシュ |
| 集計 | `contract_total_1`(①)・施工計/保安計/給与計・`cost_total_8`(⑧)・`profit_9`(⑨)・対①率 | 自動計算（表示） |
| UI | `ui_col_layout_json` 等（736流用） | 列幅・レイアウト保存 |

### 3.3 総括原価行の同期（P-21）

②のブロックフッタ「計」（＝P-22丸め済み明細合計＋手入力の諸経費・各種保険料・法定福利費。計は再丸めしない＝U25）を、`stable_block_id` で `summary_cost_lines` の対応行へ単方向投影する。単位混在ブロックは `式`×`1`×税抜合計（Q8）。

**P-33/P-39**: 金額の唯一の正は②「計」。①投影金額は表示高速化用の再生成可能キャッシュで、⑧⑨の計算入力には使わない。⑧⑨は②の`active`ブロック計＋①給与から再計算し、`retired`は現行予算0として除外する。①と②の不一致を検出した場合は版確定を拒否し、②から①へ上書き修復する。①から②への金額逆同期は禁止。

## 4. アプリ② 実行予算ver02_内訳明細

### 4.2 版複製（P-23／P-28）

次版作成時、旧版 `budget_version_id` の②レコード全件を新 `budget_version_id` で一括コピー（`stable_block_id`・`row_key` は同値コピー）。**③はコピーしない。**

**P-34原子処理**: 旧①ロック更新1要求＋①新版作成1要求＋新②コピー`ceil(N/100)`要求＋旧②`parent_lock_snapshot`更新`ceil(N/100)`要求を1回の`bulkRequest`へ格納する。要求数は`2+2×ceil(N/100)≤20`。約763行は18/20、初回上限900行。1要求でも失敗すれば全体ロールバック。タイムアウト時は`version_record_key`で成功済みか照合し、重複作成しない。901行以上は送信前中止。

**P-44通常保存**: 新版作成以外の予算編集も、①親・②追加/更新/削除・①投影キャッシュを1回の`bulkRequest`で原子保存する。③保存は現行①の`actual_write_seq`を`revision`付きで更新する要求と③書込みを同一`bulkRequest`にし、新版作成とのレースを全ロールバックで止める。

## 5. アプリ③ 実行予算ver02_実績（P-30）

### 5.1 レコード種別（`record_kind`）

| 種別 | 粒度 | 主フィールド |
|---|---|---|
| `monthly_consumption`（月別消化） | **1原価行×1月=1レコード**（縦持ち） | `project_id`・`stable_block_id`(工種キー)・`cost_category_key`(施工/保安)・`target_month`・`amount`(税抜整数)・`note`・`source_kind`(初回`手入力`)・`registered_version_id`(登録時予算版ID・監査専用) |
| `final_budget`（最終予算額） | 1原価行=1レコード | `project_id`・`stable_block_id`・`cost_category_key`・`amount`・`last_changed_version_id` |

- 実績は**工事帰属**。版複製でコピーしない（V3b/P-28）。給与手当は予実対象外（Y4）。
- 現行予算・消化率・残予算・今後必要額は**保存しない**（表示時に計算。Y10・P-30）。
- 月マトリクス表示はカスタムUIで縦→横整形。月列は着手月起点で可変（Y5／R-17は依頼者確認継続）。

### 5.2 登録時予算版ID（P-27）

保存API実行時に「下書きがあれば下書き版、なければ最新確定版」の `budget_version_id` を解決して保存。以後書き換えない。**表示フィルタ・ロック判定には使わない**（監査専用）。

## 6. ロック判定（P-26・B2解消済み）

| 対象 | 参照する親 | 判定 |
|---|---|---|
| ①予算版 | 自分 | `status=版確定`→予算ロック。同一 `project_id` に新版存在→旧版完全ロック（V11b）。`is_locked`は判定に使わない（P-38） |
| ②内訳明細 | 自分の `budget_version_id` の① | 親が下書き→編集可。それ以外→拒否 |
| ③実績 | **工事の現行版**（下書き優先→最新確定）の① | 保存要求の画面版IDが現行版IDと一致するときだけ編集可。旧版画面からは拒否 |

- ロック状態の業務上の正は①のみ。P-35により②にはレコード権限強制用の派生`parent_lock_snapshot`を持つが、判定元・修復元は常に①とし、P-34の原子処理内で更新する。③には複写しない。
- 判定は**保存API実行時に再確認**（画面表示時の状態を信用しない＝レース対策）。
- 発火は「新版レコード初回保存時」（下書きでも直接確定でも＝P-26）。

### 6.1 保存経路・権限（P-35）

- 利用者の正規接点は①だけ。②③の一覧・新規・編集導線を非表示。
- ②③の直接編集画面はカスタマイズで保存拒否。
- 正規書込みは①の共通保存処理だけが実行し、親ロック再確認・`revision`・一意キーを必須化。
- ②旧版は`parent_lock_snapshot`を条件にレコード権限でも更新拒否。
- ②③の`write_channel`は正規経路監査用。初回値は`app1_custom_ui`。
- 意図的なREST直実行の完全遮断はkintoneブラウザセッション権限だけでは保証できないため、本番移行前に外部プロキシ要否を再判定。
- 既存レコード更新・削除は全件`revision`必須。競合時は処理全体を中止・再読込（P-40）。

### 6.2 初回の最低ACL（実装前固定）

| アプリ・条件 | 一般利用者 | 実行予算管理者 |
|---|---|---|
| ① | 閲覧・正規UI操作可。過去版はJS/保存ガードで更新拒否 | 閲覧・障害調査可。通常保存は同じガードを通す |
| ② `parent_lock_snapshot=editable` | 正規UI経由の追加・更新・削除可。直接画面保存は拒否 | 修復時のみ直接操作可 |
| ② `parent_lock_snapshot=locked` | 閲覧のみ。レコード権限で更新・削除不可 | P-34失敗時の修復のみ可、監査記録必須 |
| ③ | 正規UI経由の追加・更新可。直接画面保存は拒否 | 障害調査・修復可 |

`実行予算管理者`は専用kintone組織/グループとし、一般利用者へ付与しない。意図的REST直実行の残差はP-35どおり本番前に再審査する。

## 7. P-29 重複作成ダイアログ（①のカスタムJS）

工事コード＋枝番の確定時に同一 `project_business_key` の系列を検索。
既存あり＋下書きなし→「次の版を作成しますか？」（はい=最新確定版から標準複製／いいえ=保存しない）。
既存あり＋下書きあり→「既存の下書きを開きますか？」（はい=下書きへ遷移／いいえ=保存しない）。
新規画面の入力内容を次版として保存しない（複製元は必ず最新確定版）。
