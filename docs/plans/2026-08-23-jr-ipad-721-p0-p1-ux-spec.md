## §2. P0 — いまなにを見ているか

### 2.1 画面「いまの条件」＋該当件数

| 項目 | 仕様 |
|------|------|
| 配置 | 絞込帯の直下・一覧表の直上 |
| 件数 | `filteredRecords().length`（有効／廃止・検索・部署・ステータス適用後） |
| 文言例 | `いまの条件: 表示=有効 ・ ステータス=貸出中 ・ 管理部署=本社 ・ 検索=JBIS` ＋ `該当 N 台` |
| 未絞込 | `いまの条件: （なし）` ＋ `該当 N 台`（有効のみでも N は全有効件数） |
| 更新 | 検索 input／部署 select／ステータスチップ／有効・廃止／クリア／再読込のたびに更新 |

### 2.2 一覧印刷ヘッダー

既存の `画面(…)`／`モーダル部署=…` に加え、件数を **`該当 N 台`** と明示（印刷対象 `rows.length`）。単票 A4 は変更しない。

### 2.3 主操作 1 行

ツールバー: **タイトル｜再読込｜一覧印刷｜Excel（P1・admin）**。  
新規端末／既存登録はメタバー（次番表示）に維持。

## §3. P1 — 出力とチップ

### 3.1 一覧 Excel

| 項目 | 仕様 |
|------|------|
| 対象行 | 画面の `filteredRecords()` と同一 |
| 列 | 一覧 12 列（ステータス〜備考）。**Apple PW を含む**（画面 admin 一覧と同列・DeepSeek 同意） |
| ボタン | admin のみ・ツールバー「Excel出力」 |
| ファイル名 | `JR_iPad一覧_YYYYMMDD.xlsx`（JST） |
| 技術 | `jr-ipad:bundle-dash` で SheetJS vendor を `desktop.js` 先頭に連結（jre-cloud 同型） |

### 3.2 ステータスチップ

| 項目 | 仕様 |
|------|------|
| UI | 「すべて」＋ STATUS 5 択をチップ 1 行。クリックで即 `filterStatus` 更新→再描画 |
| 部署 | **select 維持**（22 拠点） |
| 有効／廃止 | 既存ライフサイクルバー維持。active 時に廃棄チップを選んだ場合は従来どおり sync でクリア |

## §5. §50-3-8 突合メモ（2026-08-23）

1. **(a) 型**: 件数は画面=`filteredRecords().length`、印刷=`rows.length`（モーダル部署適用後）を別系統で合わせる。  
2. **(b) SPEC**: 集計クリック・720・連携は本 SPEC 外。親 SPEC 非置換。  
3. **(c) 差異**: 印刷ヘッダーの画面／モーダル併記は維持。Excel PW=画面列継承。  

**Kimi**: SheetJS 未バンドルを指摘 → bundle 改修で解消。PW 除外案は CIO 裁定で **含める**（admin 専用・画面と同列）。
