## 0. 背景・現状（コード事実）

| 項目 | 現状 |
|------|------|
| 詳細表 | `SUB_BLOCKS` 4 件固定 · `ensureSubVendorRows` / `defaultSubcontractTemplate` で **常に4ブロック生成** |
| 総括表 | `DEFAULT_COST_TEMPLATE` に ④〜⑦ **連携行が常時含まれる**（`cost_row_kind=link`） |
| 連携計算 | `calcSubcontractBlock` → `blockOrderAmount` → `applyDetailLinks` で **既に自動反映** |
| 新規ドラフト | `newDraftState()` が上記テンプレをそのまま投入 |

**結論**: 連携ロジックは **実装済み**。本 PH1d は **ブロックの有無・UI・保存形式・総括連携行の増減** を追加する。

---

## 1. 目的

塗装橋梁以外・外注ブロック不要な案件で、詳細表を **材料②③のみ** で始められるようにする。必要な外注ブロックだけ追加し、削除したブロックは総括表からも **行ごと消す**（A案）。

---

## 2. スコープ

### 2.1 対象

| 対象 | 内容 |
|------|------|
| 詳細表 | 外注ブロック **④修繕 / ⑤足場 / ⑥塗装 / ⑦労務** の **追加・削除・表示制御** |

## 3. 機能要件

### 3.1 デフォルト（新規）

| 領域 | 挙動 |
|------|------|
| 詳細表 | 材料②③のみ表示。**④〜⑦ブロックは非表示** |
| 総括表 | ②③連携行＋材料小計は従来どおり。**④〜⑦連携行は存在しない** |
| `subcontract_lines` | **空配列**（または vendor 行も含めブロック単位でゼロ） |

### 3.2 ブロック追加

| 項目 | 仕様 |
|------|------|
| 操作 | 詳細表に **「外注ブロックを追加」**（未追加の ④〜⑦ から選択。複数可） |
| 詳細表 | 選択ブロックについて `defaultSubcontractTemplate` **単ブロック分**を挿入（`SUB_LINES` テンプレ・vendor 行含む） |
| 総括表 | 対応 `detail_marker` の **連携行を1行挿入**（`DEFAULT_COST_TEMPLATE` 該当行と同型） |
| 挿入位置 | 連携行は **④→⑤→⑥→⑦ の canonical 順**を維持（存在するマーカーのみ・欠番可） |
| 連携 | 追加後の明細入力は **既存 `recalcState` / `applyDetailLinks` をそのまま使用** |

**マーカー固定表（ユーザー選択不可）**

| `subcontract_block` | ラベル | `detail_marker` | 総括連携行 `cost_work_type`（既存テンプレ） |
|---------------------|--------|-----------------|---------------------------------------------|
| `repair` | 【修繕工事】…④ | ④ | 修繕工事 |
| `scaffold` | 【足場工事】…⑤ | ⑤ | 足場工事 |
| `paint` | 【塗装工事】…⑥ | ⑥ | 塗装及び足場工事 |
| `labor` | 【労務費】…⑦ | ⑦ | 直轄施工班 |

### 3.3 ブロック削除（A案）

| 項目 | 仕様 |
|------|------|
| 操作 | 各ブロック見出しに **「ブロックを削除」**（読取専用・版ロック時は不可） |
| 確認 | ブロック内に **金額≠0 の行が1つでもあれば確認ダイアログ**（§41 相当の誤削除防止） |
| 詳細表 | 当該 `subcontract_block` の **全 `subcontract_lines` を削除** |
| 総括表 | 当該 `detail_marker` の **連携行を削除**（0 表示で残さない） |
| 再計算 | `recalcState` → ⑧⑨・小計・率を更新 |

### 3.4 保存・読込

| 項目 | 仕様 |
|------|------|
| 正本 | 従来どおり `subcontract_lines` / `cost_lines` サブテーブル（**新フィールド必須としない**） |
| 有効ブロック推論 | 読込時 `subcontract_lines` に `subcontract_block=X` の行が **1行以上** → ブロック X は有効 |
| 整合チェック | 有効ブロックと連携行の `detail_marker` が不一致なら **読込時に自動整備**（連携行追加 or 孤立連携行削除） |

## 4. 非機能・安全

### 4.1 権限・版

- **版ロック**（`is_locked`）時はブロック追加・削除 **不可**（既存行編集規則と同じ）
- deploy 前: `cio:preflight:736` · `verify:kintone-live-schema --app 736`（Warning 0）

### 4.2 PH1c / PH1b との関係

| フェーズ | 関係 |
|----------|------|
| **PH1c**（行並び替え） | **独立**。PH1d はブロック単位の出し入れ。PH1c は **7/9 以降** implement（本日は仕様のみ） |
| **PH1b 部分**（ラベル行） | 凍結。PH1d 完了後に必要なら別 GO |

### 4.3 印刷・ジャンプ

- 存在しないブロックのアンカー（`jy-sec-block-*` / `jy-sum-ref-4` 等）は **非表示**
- 番号リンク・金額ジャンプは **存在するマーカーのみ** 有効

### 4.4 版管理・差分

- 行の追加削除は `row_key` ベース差分に載る → **ブロック削除は「行削除」として表示**（仕様どおり）
- 並び替え（PH1c）未実装のため、連携行挿入位置は **canonical 順固定** で差分混乱を抑える

| ケース | 方針 |

## 6. AIチームレビュー（§50-3-8 · 2026-07-08）

**DeepSeek 盲点3点 + 突合メモ**

1. **型**: 単ブロック `defaultSubcontractTemplate` 抽出時、`sub_row_kind` / `SUB_CALC` 行がブロックごとテンプレと一致することを単体テストで検証する。  
2. **SPEC乖離**: 連携行挿入位置を「④〜⑦の canonical 順」と明文化済み（本書 §3.2）。  
3. **差異ロジック**: 版比較は `row_key` 前提 — ブロック削除は削除行として正しく出る。PH1c 未着手のため行番号依存ロジックは増やさない。

**残質問（implement 直前 §41）**

| Q1 | ブロック追加 UI は **チェックリスト** か **1件ずつドロップダウン** か | **未追加一覧から1件ずつ追加**（誤複数追加防止） |
| Q2 | ④だけ・⑥だけなど **欠番** を許すか | **許す**（canonical 順で存在行のみ表示） |
