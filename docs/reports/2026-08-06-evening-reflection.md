## 1. 失敗（事実）

| # | 事実 |
|---|------|
| 1 | 674 SKYSEA 手動フィールドの一括初期化で、kintone クエリ `not in ("完了","未了")` を使った。**空の DROP_DOWN は `not in` に載らない**ため、個人PCの未了初期化が抜け、後からクライアント側フィルタで約100件を再初期化した |
| 2 | SKYSEA 一覧印刷で `visibility:hidden` を使い、**白紙が複数ページ**出た。印刷専用ルート（`#npl674-skysea-print-root`）へ切り替えるまで目視で気づく必要があった |
| 3 | 所属セレクトを **レコードに出た所属だけ**から組み立てたため、高崎などが欠ける／関越・東京が少なく見える状態を一度出した。App680 全所属＋件数表示へ直すまで再デプロイが要った |
| 4 | 対象条件に **`pc_status=保管` の除外が遅れた**。保管除外は目視後の追修正になった |
| 5 | 一覧 UX を段階的に直しすぎた（全件表示→所属選択後のみ、所属並び未整備→680 `sort_no`）。**受入前に「所属選択→リスト→件数」の完成形を1行固定せず**、deploy 回数と目視回数が増えた |
| 6 | 旧 SKYSEA 4フィールド削除の GO 後も、checkpoint「次の1手」がしばらく **判断待ちのまま残る**更新遅れがあり、完了済み件を残課題に見せるリスクがあった（案内規律とズレ） |

## 2. 改善案（ミス削減）— 行動

| ID | 内容 | 状態 |
|----|------|------|
| **A1** | DROP_DOWN／RADIO の「未設定を初期化」は、kintone `not in` だけに頼らない。**全件（または狭いスコープ）取得→クライアントで空判定**を初手の既定にする | 反映済 |
| **A2** | 印刷系は `visibility:hidden` を使わない。**印刷ルート専用 DOM＋他を `display:none`** を初手とする（白紙ページは受入前の自己チェック項目） | 反映済 |
| **A3** | 所属セレクト／件数は **マスタ（App680）を正**とし、レコード出現集合だけから組み立てない | 反映済 |
| **A4** | SKYSEA／台帳の対象クエリは着手前に **含む種別・除外ステータスを1行で固定**してから実装する（例: 個人／保管・廃棄・取消除外） | 反映済 |
| **A5** | admin 専用一覧は、初回 deploy 前に **完成UX（選択→表示→操作→印刷）をチェックリスト化**し、途中完成で目視依頼しない | 反映済 |
| **A6** | 浜田が完了裁定した件は、同一ターンで checkpoint「次の1手／GO待ち」から外す（完了済を残課題に出さない） | 反映済 |

### 1-N 憲法運用レビュー（本日の結論）

- 実PC配信禁止・admin 限定・手動台帳切替は境界どおり守れた。憲法不足ではない。
- 失敗の主因は **kintone 空値クエリの思い込み**、**印刷 CSS 選択ミス**、**所属マスタ未使用**、**対象スコープの後出し除外**。
