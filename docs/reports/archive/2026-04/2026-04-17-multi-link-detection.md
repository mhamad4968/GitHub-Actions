## 2. 実装内容

### 627 (アカウント管理台帳) ── `customize/627/desktop.js`

- **検索パネル `WRAP_VER` を 10 → 11 に bump** し、旧パネルが残っていても自動的に新版を再描画。
- **在籍ステータスをドロップダウン化**
  - 旧: テキスト入力 (例: 「在籍」と完全一致を手打ち)
  - 新: `<select>` で「すべて / 在籍 / 休職 / 退職」を選択。kintone DROP_DOWN 型に正しく `in ("値")` で渡す既存の `build627ListQuery` ロジックをそのまま活用。
- **チェックボックス「📌 PCが複数紐付き（間違い探し）」を追加**
  - `build627IdsHavingMultiplePcsQuery()` を新規実装。
  - 627 を全件 fetch し、各レコードの `pc_594_record_id`(単独) と `pc_ledger_links` サブテーブル内 `pc_ledger_link_594_id` を **和集合** して 2 件以上のものだけ ID 化。
  - 結果は `$id in (...)` の形に整形し、他の検索条件と and 結合して `navigate627ListWithQuery()` に渡す。
  - 失敗時はモーダルで通知（黙って 0 件にしない）。
- ヘルプテキストを「📌 の挙動」を含めて更新。

### 594 (PC台帳) ── `customize/594/desktop.js`

- 検索パネル上段ショートカット行に **「📌 アカウント複数/重複疑い」トグル**を追加。
  - 既存の「棚卸未了 / 本年分棚卸完了 / 台帳未紐付」と同じスタイル系統で、警告色 (橙→押下時は赤) で見分けが付くように。
- データ集計ヘルパー `buildMultiAcct594IdSet()` を新規実装。
  - **判定 (A) 627 → 594ID 逆引き**: 627 全件を取得し、`pc_594_record_id` + `pc_ledger_links.pc_ledger_link_594_id` を 594ID 別カウント。**2 件以上のものを対象**。
  - **判定 (B) 594 内 ledger_record_id 重複**: 594 全件で同じ `ledger_record_id` を共有する別 PC があれば対象（買替 / 引き継ぎで旧 PC に ledger 番号が残っているケース＝間違い探し向け）。
  - 5 分間メモリキャッシュ。トグル ON 時に集計、OFF 時はキャッシュ温存。
- `doTableSearch()` / カードビューの `doSearch()` 双方のフィルタに `mMultiAcct` を追加。**他の条件と and 結合**するため、所属で絞った上での重複候補抽出も可能。
- `captureSearchState` / `applySearchStateToUi` / `clearSearchState` に `shortMultiAcct` を追加。`sessionStorage` に永続化される他のトグルと完全に同じ振る舞い。
- 復元時に `shortMultiAcct === '1'` の場合は **集計を await してから描画** (キャッシュ未温の状態でフィルタが空にならないようにガード)。
- リセット (リセットボタン / 条件をクリアバナー) も `shortMultiAcct = 0` を確実に戻す。

## 6. 注意・補足

- 627 の「📌 PCが複数紐付き」は API 全件走査のため、最大 1 秒程度のロードがあります（306 件規模なら 0.5 秒未満）。
- 594 の「📌 アカウント複数/重複疑い」は 627 と 594 の双方を全件走査するため、初回 1〜2 秒。**5 分以内の再操作はキャッシュで即時**。
- 復元キーは sessionStorage の既存キー (`jbis594_search_state_v1:<viewId>`) に同居しているため、ブラウザを閉じると消えます (永続化はしません)。
- `ledger_record_id` が同じものを複数 594 が抱えるパターンは、買替時に旧 PC のリンクを抜き忘れているケースが大半なので、本機能で炙り出した上で旧 PC 側の ledger を空にすると整流されます。
