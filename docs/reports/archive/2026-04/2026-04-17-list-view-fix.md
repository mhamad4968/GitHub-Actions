### 原因チェーン (修正前 = rev463以前)
1. ユーザーが**カード表示ビュー**（CUSTOM）で「個人」など条件を入れて検索
2. 検索条件が `sessionStorage` の `jbis594_search_state_v1:<viewId>` に保存される
3. ユーザーがビュー切り替えで「**PC台帳（表形式全表示）**」(LIST)に移動
4. テーブル描画ハンドラが起動し、`fetchAllForCurrentView` 完了後に **`applySearchStateToUi(savedSt)` が true を返すと自動で `doTableSearch()` 発火**
5. `hasFilter=true` → `hideDefaultTable()` でテーブル消滅 → `renderCardsIfNeeded()` でカード描画
6. 結果: **「表形式全表示」のはずなのに、カードビューが表示される**

> 注: ビュー別のキーで保存しているため、同じLISTビュー内で前回検索→詳細→戻った時にも同じ現象が発生していました。

## 2. 修正内容（rev464）

### F1. 自動カード化の撤廃 ★中核
表形式ビューでは、`sessionStorage` に検索条件が残っていても**自動で `doTableSearch()` を呼ばない**ようにしました。

```js
// 修正前
const savedSt = loadSearchState();
if (applySearchStateToUi(savedSt)) {
  doTableSearch();  // ← これで勝手にカード化されていた
}

// 修正後
const savedSt = loadSearchState();
const hasRestoredCond = applySearchStateToUi(savedSt);
showDefaultTable();  // 必ずデフォルトテーブルを出す
if (hasRestoredCond) {
  if (countEl) countEl.textContent = `全${allRecs.length}件（前回の検索条件あり）`;
  showRestoreBanner();  // ★ バナーで明示
}
setPanelFilteredVisual(false);
```

### F2. 「前回の検索条件あり」バナーを追加
全件表示は維持したまま、検索パネル直下に**警告色オレンジのバナー**を表示:

```
⚠ 前回の検索条件がパネルに残っています（現在は全件表示）。
   [この条件で絞り込む] [条件をクリア]
```

- 「**この条件で絞り込む**」ボタン → 即`runTableSearchAndSync()`実行
- 「**条件をクリア**」ボタン → リセットボタンと同じ動作

ユーザーに**「全表示なのか / 絞り込み中なのか」を一目で判別**させ、選択権を渡します。

### F3. 「絞り込み中」を赤枠で視覚明示
絞り込みを実行した瞬間、検索パネル全体が**赤いアウトライン+桜色の背景**に変化:

```js
panelEl.style.outline = '2px solid #b91c1c';
panelEl.style.background = '#fef2f2';
```

リセットすると元の見た目に戻ります。

### F4. リセットボタンの視認性UP
従来の地味な白ボタンから、**警告色のオレンジボタン**に強化:
- 背景: `#fff7ed` → ホバーで `#fed7aa`
- 枠: 1.5px の `#b45309`（茶系）
- テキスト先頭に `↺` アイコン自動付与

これでユーザーがリセット可能性を見落とさなくなります。

### F5. トグルボタン（棚卸未了など）も視覚同期に統合
従来は `doTableSearch()` を直接呼んでいましたが、**`runTableSearchAndSync()` 経由**に変更。
トグルを押した瞬間にも赤枠ON/OFFが正しく同期します。

### F6. `showDefaultTable` でカード残骸を確実にクリア
万一前回のカード描画コンテナに残骸があった場合に備え:

```js
const showDefaultTable = () => {
  // ... テーブルのdisplayプロパティ復元
  tableSearchContainer.style.display = 'none';
  tableSearchContainer.innerHTML = '';  // ← 追加: 残骸を確実消去
};
```

これで「テーブル＋カードが重なって見える」事故の最後の経路も塞ぎました。

### F7. カードビュー(CUSTOM)では既存動作を維持
カード表示が前提のビューでは、検索状態の自動復元→自動絞り込みのままです（カード→カードなので違和感なし）。修正は表形式LISTビューだけに限定しました。

## 6. 結論

「**表形式全表示なのにカード表示が出ている**」という違和感は、**自動検索条件復元によるカード化発火**が原因でした。修正では:

1. **テーブルビューの初期表示は必ず全件テーブル**を保証
2. 残存条件は**オレンジバナーで視覚明示**＋**ワンクリック適用/クリア**
3. 絞り込み中は**赤枠で識別性UP**
4. リセットボタンを**警告色で目立たせ**、見落としを防止

これでユーザーは「**今、自分が全件を見ているのか、絞り込みを見ているのか**」を常に明確に判断でき、混乱なく操作できます。
