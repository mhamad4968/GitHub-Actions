# 仕様変更は同ターンで書面反映 — 浜田厳重注意（2026-07-23）

**発端**: 2026-07-22 夕に UI で確定した「工事基本情報＝別タブ」「予実2段表示」等を、締め時の「仕様変更があれば対応」指示があったにもかかわらず **書面 SPEC へ同ターン反映しなかった**。翌 2026-07-23 の監査が旧§6.1（4タブ・総括内包）を正と誤認し、UI を巻き戻す事故が発生。

## 規則（即時適用）

1. **画面・用語・タブ構成・率ラベル**など製品仕様を変えたら、**そのターン内**に正本 SPEC（現状 `docs/plans/2026-07-19-jikkou-yosan-ver02-redesign-spec-draft.md`）を更新する。
2. deploy / commit / 締めのどれより **SPEC 追記が先**（または同一 commit に必ず含める）。
3. 「明日の仕様総点検で直す」「監査で判定」は **仕様変更の代替にならない**。
4. 締め指示に「仕様変更があれば対応」とある場合、**未反映の口頭・チャット確定を SPEC に落とすこと**を必須チェックとする。
