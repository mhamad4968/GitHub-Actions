# エージェント向け：復元チェックポイント（チャット無しでも文脈を戻す）

Cursor / Claude は**会話全文を自動で永続化しない**。チャットが切れても、**いまの作業の「途中経過」**を短いファイルに残すと、新しいセッションですぐ拾い直せる。

## 正本との優先順位（最重要）

**チェックポイントはあくまで作業メモである。次と矛盾したら、常に正本側を採用する。**

1. ユーザーがチャットやルールで明示した**最優先の指示**
2. **`.cursor/rules/*.mdc`**
3. **`kintone-apps.md`**（フィールド・履歴・アプリ間マップ）
4. 本リポの **`CLAUDE.md`**
5. **`types/kintone-*.d.ts`**・**`docs/*.md`** の事実記述
6. **`RULES-INDEX.md`** の随時メモ（索引）
7. **`chat-sessions/checkpoint-latest.md`** … 上記を**上書きしない**。**古い記述が残っていれば正本で上書き判断**し、チェックポイントを直すか `(要確認)` と残す。

## ファイルの役割

| ファイル | 役割 |
|----------|------|
| **`chat-sessions/checkpoint-latest.md`** | **常に最新の「復元ポイント」**。セッションの区切り・大きな方針転換のあとに更新する。**短く**保つ（長文化したら日付別アーカイブへ移す）。 |
| **`chat-sessions/YYYY-MM-DD.md`** | その日の詳細ログ・試行錯誤（任意・従来どおり）。 |
| **`RULES-INDEX.md` 1 行** | **恒久に効く決定**の索引（従来どおり）。 |

## `checkpoint-latest.md` に書く内容（目安）

- **最終更新日時（UTC かローカルで統一）**
- **いまのゴール**（ユーザーが望んでいたことを 1〜3 行）
- **着手中のアプリ ID / ブランチ / PR**（あれば）
- **未完了タスク**（チェックリスト可）
- **次のセッションで最初にやること**（1〜3 項目）
- **触った正本**（例: `customize/594/desktop.js` rev 433）— 数字は**推測で書かない**
- **ブロッカー**（`.env` 不足・権限・方針未決定など）

**書かないもの**: シークレット、トークン、個人情報、正本に載せるべきフィールド仕様の「確定事実」（それは `kintone-apps.md` 等へ）。

## コールドスタート時（エージェント）

1. システム / Cursor から **`.mdc` 等のルール**を読む（既定どおり）。
2. **`CLAUDE.md`** の優先順位・儀式を確認。
3. **`chat-sessions/checkpoint-latest.md`** を開き、**空・プレースホルダのみならスキップ**してよい。
4. 内容を読んだら **`RULES-INDEX.md`**・**`kintone-apps.md`** と突合し、**矛盾は正本で解決**。
5. 実装作業なら **`CLAUDE.md`「セッション開始時の作法」**（Health Check 等）を続けて実行。

## 人間向け：新しいチャットでの指定例

```text
@CLAUDE.md @RULES-INDEX.md @chat-sessions/checkpoint-latest.md
（または checkpoint の内容を貼り付け）
続きから [具体的な依頼]
```

## 長い作業のアーカイブ（任意）

`checkpoint-latest.md` が長くなったら、抜粋を **`chat-sessions/checkpoints/YYYY-MM-DD-_TOPIC.md`** にコピーし、**`checkpoint-latest.md` は短い「現在地」だけ**に戻す。`checkpoints/` 内の古いファイルは**削除しない**（監査・再参照用）。

## 「忘れた」を防ぐ（トリガー・締め・役割分担）

記憶はチャットに依存しない。**「いつファイルに書くか」**を決めておくと漏れが激減する。

### エージェントが必ずストックを疑うトリガー（いずれかで発火）

次の**いずれか**が起きたら、**チャットで完結させない**。**報告・区切りの直前**に、どこへ書いたかを自問する。

- **未完了**が残る（次セッションに持ち越す）
- **`kintone-apps.md`・`docs/*`・`customize/*`・ワークフロー**など**正本を変更**した（またはデプロイして「事実」が変わった）
- **方針・トレードオフ**をユーザーと決めた（チャットだけだと次回消える）
- **ブロッカー**（`.env`・権限・仕様未確定）がある
- **「あとでやる」**が1件でも出た

### セッション締めの 4 点（迷ったらこの順）

| 優先 | 書く場所 | 何を |
|------|----------|------|
| 1 恒久 | **`RULES-INDEX.md` 1 行** と／または **該当正本** | **次回以降も効く決定**・例外ルール・参照パス |
| 2 現在地 | **`checkpoint-latest.md`** | **いまのゴール・未完了・次に最初にやること**（短く） |
| 3 詳細 | **`chat-sessions/YYYY-MM-DD.md`**（または会話メモ） | **試行錯誤・コマンド・長い文脈** |
| 4 Git | **`git commit`**（**必須**） | 本セッションの差分を **未 commit のまま締めない**。`npm run verify:session-close-git-warn` が **exit 1** なら締め未完 |

**締め儀式の機械順**（`desktop:sync-and-verify` 連動）: handoff 更新 → **`git commit`** → `npm run cio:session:export-handoff`（gitHead 同期）→ bridge 追記があれば再 commit → `npm run desktop:sync-and-verify`。

**1 が空で 2 だけ、はよくある**（実装続きなら可）。**2 が空のままチャットだけで終わる**のが一番危険（翌セッションで文脈ゼロ）。

### 完了報告・黄金 3 ステップとの接続

**`CLAUDE.md`「作業完了報告」**を書く直前に **10〜30 秒**でよいので、上表の **1〜2** を満たしたか確認する。**未完了があるのに checkpoint を更新していない**なら、報告の「次のアクション」と **矛盾しないよう** `checkpoint-latest.md` を直す。

### 人間側のコツ（負荷を足さない）

- チャットを閉じる／席を離れる前に **一言だけ**: 「**チェックポイントと INDEX 残して**」または「**今日のところ、`checkpoint-latest` 更新して**」
- **`npm run chat:today`** で日次メモのパスを出し、**1 行でも**「決まったこと」を書く
- **週次または区切りで `npm run backup`**（チェックポイント類もバックアップ対象）
- **カレンダー／タスク**に「金曜：INDEX と backlog を見る」など**リマインダのみ**置く（中身は正本が持つ）

### うっかり消し込み（リカバリ）

- **checkpoint が古い**と気づいたら、**正本と diff**し、古い記述に **`(要確認: 日付)`** を付けてよい（推測で上書きしない）
- **永続ルールをチャットだけで言った**ことに気づいたら、**すぐ `RULES-INDEX.md` に 1 行**（ユーザー承認が要る内容は追記前に確認）
