> **位置づけ**: **経営会議レポート本体（doc-lane / R7）とは別レーン**

## 0. 何のためのものか

経営会議の **情報セキュリティレポート依頼の前**に、浜田が「どの話題を注意喚起にするか」を決めるための **判断材料（ネタ一覧）**。

| やる | やらない |
|------|----------|
| 前月の他社重大事例を 701 相当からピックして一覧化 | 経営会議提出用 DOCX の §1 起稿・§2 数値・提出本文 |
| おすすめ度付きで選択幅を広げる | ネットを一から探し直す（原則） |
| 必要なら AI に「どれにするか」相談 | ネタ作業と資料作成を同一依頼で混ぜる |

**経営会議レポート正本**: `docs/runbooks/keiei-kaigi-security-report.md`（R7）  
ネタで話題が決まった **あと**、別依頼でレポート作成に入る。

---

## 1. 依頼の言い方（浜田）

例:

- 「経営会議〇月のネタを作って」
- 「〇月分の注意喚起ネタを `C:\tmp\資料作成\ネタ保存用` に」

AI は **ネタレーンのみ**完遂し、経営会議資料作成には勝手に進まない。

---

## 2. データ源

**作業開始時にチャットへ1行明示（OPS-2）**: `データ経路: UX=701 / REST=631`。

| 役割 | アプリ | 備考 |
|------|--------|------|
| 掲示板（人が見る入口・UX） | **[701](https://jbis-kintone.cybozu.com/k/701/)** | Space 48。CVE/パッチ系は表示除外 |
| REST 正本（AI 取得） | **631** | 701 は 631 を読む掲示板。収集は 631 |

- **対象期間**: 経営会議「〇月分」→ **前月の `published_date`**（例: 8月分ネタ → 7月公開）
- **フィルタ**: 701 と同趣旨（インシデント優先、NVD/CVE・パッチ告知は除外）
- **件数**: 固定しない。重要候補は載せる（AI 裁量）。多いほど選択幅が広がる想定
- **並び**: おすすめ度（重要度）降順

## 3. 成果物の置き場

```
C:\tmp\資料作成\ネタ保存用\
  yyyymmdd\          ← 作成日 JST（例: 20260810）
    *-一覧*.docx     ← 浜田が読む主成果（表形式・全文・省略禁止）
    *.md / *.json    ← AI 再加工・出典参照用
```

- DOCX は **Git にコミットしない**（R-DOC-04 と同趣旨・`C:\tmp` 作業物）
- フォルダ説明: 同ディレクトリの `README.txt`

---

## 4. Word 一覧の必須列

**省略禁止（T3 / R2）**: セル文の `…`／三点リーダ切りは禁止。全文。

| 列 |
|----|
| 発生日 |
| 概要 |
| 原因 |
| 気を付けなければいけない事柄 |
| おすすめ度（重要度） |
| 現在の状況 |
| 被害額 |

**冒頭に必ず**: 「何を注意喚起するべきか（案）」— 前月全体の傾向から社内周知テーマを数点。

原因・被害額・現状が元データに無い場合は **「未確定（調査中）」** と明記（空欄にしない）。

**納品前チェック（OPS-3）**: DOCX／md に `…` が残っていないこと（機械検索または目視）。残っていれば出し直し。

---

## 5. AI 手順（要約）

1. 依頼月を確認 → **データ経路: UX=701 / REST=631** を1行宣言 → 前月の日付範囲で 631 を取得（`published_date`）
2. 701 相当フィルタでインシデント候補を抽出・おすすめ度付与
3. `C:\tmp\資料作成\ネタ保存用\yyyymmdd\` に DOCX（表）＋ md/json（省略禁止・未確定表記）
4. 納品前に `…` 無しを確認
5. チャットは **保存先と件数・注意喚起案の所在**だけ短く報告
6. **経営会議資料作成には進まない**（別依頼待ち・T6）
