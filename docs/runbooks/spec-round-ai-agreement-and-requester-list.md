# 仕様ラウンド AI 合意 ＋ 依頼者確認リスト（運用）

> **制定**: 2026-07-20（夕反省 #R-SPEC-01 / #R-REQ-01・浜田全部承認）  
> **目的**: 条件付き合意での CLOSED 誤認と、依頼者リストの画面偏りを防ぐ。

## 1. AI 最終合意 — 無条件のみ（#R-SPEC-01）

浜田が仕様ラウンドで **「無条件合意のみ」「条件付きは不可」** と明示したとき:

1. AI／第2者の判定が **条件付き YES／条件付き NO／残OPENありで CLOSED 可** なら **不合格**。
2. 残っている任意・OPEN を、次のいずれかで **先に仕様固定**する（浜田に再確認が要るものは依頼者リストへ）。
   - 既存アプリ流用（例: 736 にあれば流用、無ければ設けない）
   - 実装詳細へ委譲（編集可否表が正、UI細部は実装時）
3. 固定後に **再投票**し、全員が **無条件 YES** のときだけ CLOSED・commit／push。
4. チャット・仕様書に「条件付きで CLOSED」と書かない。

## 2. 依頼者確認リスト — 4画面必須（#R-REQ-01）

依頼者（施工部など）へ出す確認リストは、必ず次の **4見出し**で棚卸しする。

| 見出し | 空のとき |
|---|---|
| **総括** | 「確認事項なし」と明記 |
| **内訳** | 同上 |
| **予実管理** | 同上 |
| **版管理** | 同上 |

- 直近ラウンドだけ書いて他画面を省略しない。
- 文面の既定は **施工部向けの平易な箇条書き**（専門略語・内部 ID は括弧か脚注に）。
- 仮置きは「仮の案・変更可」と明示する。
