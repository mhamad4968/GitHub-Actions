# 依頼者／施工部向け資料レビュー（1件ずつ）

**制定**: 2026-07-26（夕反省 #OPS-01 / #R-REVIEW-01 / #TEAM-01 GO）  
**目的**: 指摘の一気出し・早合点・誤報を防ぐ。

## 必須

1. **1応答＝1指摘**（#OPS-01 / #R-REVIEW-01）。次件は浜田の「次」待ち。
2. 画面挙動（手動／自動など）を断定する前に、**該当の commit／判定関数を Read**（#OPS-02 / #R-UI-READ-01）。未読なら「未確認」。
3. DOCX／Office 指摘は **画面突合**後（#OPS-03 / #D-DOCX-01）。正本: `docs/runbooks/docx-review-screen-check.md`。
4. 欠落・項番の指摘前に「意図的省略か／メール項番対応か」を **1問確認**（#OPS-04）。
5. 資料レビューターンでも **第2者に事実誤認・早合点の短問**を挟む（#TEAM-01）。不能時は `§50-3-8 スキップ理由:` 1行。

## 中間報告（#TEAM-02）

中間報告でも checkpoint「最終更新」と bridge.gitHead の鮮度を自己申告する（締め専用とみなさない）。
