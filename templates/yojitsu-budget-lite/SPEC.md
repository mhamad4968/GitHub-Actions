## 0. 課題と要件（浜田説明・2026-04-28 反映）

- **現状**: 同一 Excel ブックで **予算管理は回っているが、実績管理がうまくいっていない**。
- **kintone 化の要件**: **予算管理と実績管理の両方**を kintone 上で行えるようにする（四つ柱のうち **実績**を運用の主戦場に載せる）。
- **年度の区切り**: **1 年分＝5 月〜翌年 4 月**で集計・管理する（Excel「新フォーマット」と同じ年度境界）。
- **技術方針**: **JavaScript（customize）と kintone REST API** を主に使う。**有償の kintone プラグインは採用しない（NG）**。公式の計算フィールド・ルックアップ等の標準機能はコスト観点で可（プラグイン市場の有償製品は使わない）。
- **運用の正とダッシュボード（浜田・確認 6 以降・2026-04-28）**: **`新フォーマット` 相当の集計・状態管理はダッシュボードアプリで行う**。浜田原文の **「セクセル管理」**は、本 SPEC では **Excel ブック上のセル単位で日常的に数字を持ち回す運用**と解釈し、**それを完全に廃止**する（数値の運用正は **kintone**）。別の用語意図なら訂正する。

## 1. 目的

- システム推進室の **年度予算と月次の予算・実績・消費率・予算修正** を、**レイアウトは Excel「新フォーマット」に整合**しつつ、**運用の正は kintone** に置く。
- **実績**を含む月次運用を **kintone 入力アプリ**で行い、**集計・俯瞰はダッシュボードアプリ**で行う（Excel セルでの日常運用は行わない）。
- kintone 化の **第 1 段**では「誰が何を入力し、どこまでをアプリの正とするか」を明文化し、後続のフィールド設計・取込設計の前提を揃える。
- **集計・俯瞰**: 明細入力用のレイアウトとは別に、**集計用のフォーマット**を用意し、**ダッシュボード形式**で見られるようにする想定（詳細は §6b）。

## 2. 用語

- **予算**: 当該月度における計画額（Excel 行 4 相当の「予算」列）。
- **実績**: 当該月度における実績額。**どの月の実績に計上するか**は **支払日（出納日）が属する暦月**を正とし、**入力した日**では帰属しない（§8）。
- **消費率**: 予算に対する実績の比率。派生値として扱い、**入力は受け付けない**方針（実装は計算フィールド等）。
- **予算修正**: 当該月度における予算の修正値（Excel の「予算修正」列）。
- **明細行**: 工種名称・工種コード・費用種別・摘要・会社等のキー列を持つ **1 行分**（Excel 行 5〜に相当）。**1 明細行 = kintone 1 レコード**とする。
- **摘要（請求内容）**: 会社に対しては **複数の請求書がまとまって届く**ことがあるため、運用上の **整理・集約の主軸**は **請求書単体ではなく「摘要（請求内容）に相当する説明」＝明細行のキー**とする（§6）。
- **集計用フォーマット**: 明細レコードの一覧レイアウトとは別に、**指標・小計・比率**などを俯瞰しやすく並べた **見せ方の設計**（ダッシュボードの中身に相当）。
- **ダッシュボード**: 上記集計を **1 画面（または少数タブ）**に集約し、室長・担当が状態を素早く把握する UI。実装は **kintone 標準のグラフ・集計**と **customize（JavaScript）**を主とし、**有償プラグインは使わない**。

## 6. kintone 化の範囲（データモデル方針）

**浜田合意（2026-04-28）**: シート **`新フォーマット` に存在する項目はすべて kintone に載せる**（左端の明細キー列・**12 ヶ月 × 四つ柱**・**右側の集計列ブロック**＝摘要別集計・固定費／変動費小計等を含む。抜け列を作らない）。

- **レコード粒度**: **明細 1 行 = 1 レコード**（`shin-format-excel-layout.md` の行 5〜相当）。
- **請求書と明細の関係（浜田提案・2026-04-28）**: 取引先から **請求書が複数まとめて**来る前提のため、**レコードの正本は請求書1枚ではなく「摘要（請求内容）」に紐づく明細行**とする。複数請求・複数回払から発生した金額は、**同一明細レコードの該当月次実績へ合算**する（支払日ベースの帰属は §8 のとおり）。請求書は **別マスタアプリにしない**（初期）。PDF は **添付**、番号は **`支払内訳` の任意列**（§6c）。
- **月度（12 ヶ月 × 予算・実績・消費率・予算修正）**:  
  - **推奨（実装案）**: **サブテーブル 12 行**（1 行 = 1 ヶ月）。各サブ行に「予算」「実績」「予算修正」を入力可能フィールドとし、**消費率は計算**（予算が 0 のときの扱いは実装時に定義）。  
  - **子アプリ・月別親レコード方式**は、権限分割やレコード数上限が理由で必要になった場合のみ再検討する。
- **消費率**: **計算のみ**（手入力不可）。
- **右側の集計列**（列 BC 付近〜。セル結合が多い）: **kintone 側にも表現する**（**有償プラグインは使わない**）。Excel 上の集計式に相当する部分は **計算フィールド**、複雑なものは **customize（JS）や API 連携で同期・再計算**するか、フィールド設計フェーズで **列ごとに入力／計算の別**を割り当てる。リポの列一覧下書きは `npm run yojitsu:excel-draft` で追補可。

## 6b. 集計用フォーマットとダッシュボード（想定）

**浜田案（2026-04-28）**: 明細データを **`新フォーマット` 相当のフィールド**で保持しつつ、**集計用のフォーマット**を別途設け、**ダッシュボード形式**で見られるようにしたい。

- **浜田追加（確認 6・2026-04-28）**: **`新フォーマット` 相当の内容をダッシュボードに載せ、集計管理をそこで行う**。Excel 上のセルでの集計表まわしは **行わない**。
- **役割の分け方（案）**  
  - **明細ビュー**: 行単位の入力・照合（Excel の表に近い）。§6 のレコード＋サブテーブル。  
  - **ダッシュボード**: 月次・費用種別・工種横断などの **俯瞰**および **集計管理の主画面**（カード／グラフ／表のハイライト）。集計の「見せ方」と **運用の集計**をここに寄せ、**単一の数値の正**が二重にならないようフィールド設計フェーズで整理する。
- **プラグイン NG 下の実装候補**（併用可）  
  1. **カスタマイズ JavaScript**（ポータル風トップ、複数ウィジェット）  
  2. **kintone 標準のグラフ・集計**（アプリ内のグラフ設定・一覧の絞り込み）  
  3. **REST API** で集計結果だけを定期ジョブが書き込む **読み取り専用の集計用レコード**（別アプリまたは同一アプリ内の別フォーム）— 必要になった場合のみ。
- **アプリ分割（相談への推奨案・AI）**: **入力用アプリ**と **集計（ダッシュボード）用アプリ**を **別アプリに分ける**のを推奨する。  
  - **分ける利点**: フィールド数が多い「新フォーマット全列」入力画面と、読み取り中心の俯瞰 UI を **責務分離**できる。**権限**も「全員が明細を編集」「室長のみがダッシュを編集不可で閲覧」などを切りやすい。集計値の再計算は **API またはルックアップ**で入力アプリを参照し、**二重入力**を避けやすい。  
  - **同一アプリに寄せる場合**: デプロイは軽いが、**一覧＋詳細＋JS ダッシュ**が 1 アプリに積み上がり、フィールド上限・画面の複雑さ・権限の細分化が不利になりやすい。  
  - **結論（仕様ドラフト）**: **アプリは最低 2 本**（①予算・実績・修正の **入力・管理** ②**集計・ダッシュボード**）。**マスタ**（工種コード・費用種別・取引先会社名など）は **必要に応じて別アプリ**または **CSV＋定期取込**で用意し、入力アプリから **ルックアップ**等で参照する（マスタ無しで開始し、運用で増やしてもよい）。

## 8. 取込・運用

- **初回取込**: **CSV エクスポート**（結合解除済みシートを正）または **手入力**。併せて、**kintone REST API** による一括登録・差分更新（CLI / cron / GitHub Actions 等は別途決定）を **主な連携手段**とする（プラグイン不使用）。
- **結合セル**: 取込正本は **結合解除済みコピー**とする（`shin-format-excel-layout.md` のメモに同趣旨）。
- **更新頻度・月次締め**（浜田合意 2026-04-28）: **各対象月はその月の暦日の末日（月末）を締め**とする（例: 5 月分は **5/31**、2 月分は **平年 2/28・閏年 2/29**）。**翌月営業日締め**にはしない。
- **実績の計上基準（浜田合意 2026-04-28）**: **入力ベースではなく支払日（出納日）ベース**とする。すなわち、**支払日が属する暦月**の「実績」に計上する（支払が翌月に跨がる取引は **翌月の実績**）。  
  - **Excel「新フォーマット」**に支払日列が無い前提のため、kintone では **`支払内訳` サブテーブル**で支払日＋金額を持ち、**月次実績へロールアップ**する（詳細・代替経路は **§6c**）。**集約のキーは摘要に紐づく明細行**（§6）。
