# 旧フォーマット → kintone 初回移行仕様

**目的**: 現データが **`旧フォーマット` シート**にある前提で、**一度限り** kintone 入力アプリ（§6・§6c・`SPEC.md`）へ流し込む。**移行後の正は kintone のみ**（`SPEC.md` §3・§8）。

**関連**: `SPEC.md` §0b、§3、§8、§10。レイアウト正本は `shin-format-excel-layout.md`（**移行先の形**）。

---

## 1. 前提・禁止事項

- **読み取り元**: ブック内シート **`旧フォーマット`**（月1列・起票日／出納日など。`SPEC.md` §0b の行×列目安）。
- **列見出しの位置（浜田・2026-04-28）**: **ヘッダは行 2**。列名の並びは **C 列から始まる（起点セル C2）**。
- **A・B 列（浜田・2026-04-28）**: **`旧フォーマット` において** — **A 列はブランク**。**B 列は通し番号**（行の連番）。移行先では kintone の **レコード番号は別採番**のため、B は **突合・ログ用**に使うか、任意で「旧通番」フィールドへ写してもよい（必須ではない）。
- **データの性質（浜田・2026-04-28）**: 当シートは **予算取得時に得た 2026 年度の実予算データ**が入っており、**初回移行では必ず参照・取り込み対象とする**（省略不可）。数値の信頼できる一次ソース。
- **書き込み先**: kintone **入力アプリ**のレコード（明細 1 行＝1 レコード、月次サブテーブル 12 行・**各月 4 列相当**、`支払内訳` は §6c）。**旧シートの列並び・月の持ち方は kintone のフォームと異なる**。
- **禁止**: 移行完了後に **旧シートへ数値を戻す**、**Excel を継続正として同期**する（`SPEC.md` 確認 9）。

---

## 2. CSV 作成時の注意（フォーム相違・必読）

旧は **月 1 列型・起票／出納日**など、kintone 側は **12 ヶ月 ×（予算・実績・消費率・予算修正）＋`支払内訳`**（`SPEC.md` §6・§6c）と **フォームが一致しない**。

| リスク | 対策 |
|--------|------|
| **そのまま「名前を付けて保存 CSV」**すると列がズレ、**結合セル**で行が壊れる | **結合解除済みコピー**から export するか、**スクリプトでセル座標指定**で読む。**ヘッダは行 2、列見出し左端は C 列（C2）**（§1）。 |
| **旧の列順＝kintone のフィールド順**と誤認 | **§3 列対応表どおりに並べ替え・分割・集約**した **別物の中間 CSV** を作る（旧 CSV をそのまま REST に流さない）。 |
| **月の対応**（旧の暦月列 vs 年度 5 月始まり） | **5 月〜翌 4 月**の対応表を §3 または別表で明示し、**1 セルずつ**突合する。 |
| **実績・出納日** | 旧の出納日は **`支払内訳` 行**へ落とし、月次実績はルールどおりロールアップ（**§6**）。 |
| **消費率** | 旧から拾わず、移行後 **計算**に任せる（**§3** 変換方針）。 |

**AI・作業者への依頼**: CSV を生成する際は **必ず §4 列対応表を開き**、不明列は **推測で埋めない**（要確認フラグを立てる）。

## 3. 変換方針（確定レベル）

| 観点 | 方針 |
|------|------|
| **予算** | 旧シートの **各月の予算相当列**を、移行先の **該当月の「予算」フィールド**（サブテーブル行）にマッピングする。 |
| **実績** | **支払日（出納日）ベース**（`SPEC.md` §8）。旧の **出納日＋金額**から **`支払内訳` 行**を生成し、月次「実績」は **ロールアップ**で埋める（または初回のみスクリプトで月次実績に直接書いてもよいが、**正規ルートは §6c** に寄せる）。 |
| **消費率** | **入力しない**。移行後は計算フィールドまたは JS／バッチで再計算。 |
| **予算修正** | 旧に明示列があれば対応列へ。無い場合は **0 または空**で開始し、運用で kintone に追記。 |
| **明細キー** | 工種名称・工種コード・費用種別・摘要・会社等、旧の列→ kintone の同一意味フィールドへ **1:1 または合成ルール**で対応（下記 **§4** で列レター確定）。 |

## 4. 列対応表（要・本日埋め）

> **本日の仕様作業**: **行 2**をヘッダとし、**C 列以降**の Excel 列番号と **kintone フィールドコード（案）**を下表に **もれなく**転記する（**A・B 列も**用途があれば先頭に書く）。不明列は「スキップ／固定値／要浜田確認」と明記する。**この表がないまま CSV を量産しない**（§2）。

| 旧 `旧フォーマット` 列（例: A, B, …） | 行番号（ヘッダ行） | 意味 | kintone 側（フィールド／サブテーブル） | 備考 |
|--------------------------------------|-------------------|------|------------------------------------------|------|
| A | 2 | （ブランク） | 対象外／空 | ヘッダもデータも空 |
| B | 2 | 通し番号 | 任意「旧通番」または移行スクリプトの突合キーのみ | レコード $id とは別 |
| （C 以降を追記） | | | | |

## 5. 手順（実装フェーズ用チェックリスト）

1. [ ] 旧シートを **結合解除済み CSV** または **スクリプト直接読取**で正規化する（§2）。
2. [ ] **§4 列対応表**に従い **中間 JSON／CSV**（kintone レコード形）を生成する（旧 CSV をそのまま使わない）。
3. [ ] **ステージング**（テストアプリまたは本アプリの下書きスペース）で **件数・合計額**を旧と突合する。
4. [ ] **REST API 一括登録**（または公式ツールで可だが **再現性**のためスクリプト推奨）。
5. [ ] 突合 OK 後、**旧シートを編集しない**運用に切り替える（`SPEC.md` §10 の運用開始目安と連動）。

---

## 6. 検証・合算ルール

- **件数**: 旧のデータ行数（ヘッダ除外）≒ kintone 明細レコード数（**1 旧行＝1 レコード**を原則。分割ルールがある場合は **§4** に記載）。
- **金額**: 旧の **月別予算合計** と kintone の **該当月予算**合計を **月度ごと**に比較。
- **実績**: 出納日が複数行に分かれている場合は **`支払内訳` 複数行**に落とし、月次実績と整合を取る。
