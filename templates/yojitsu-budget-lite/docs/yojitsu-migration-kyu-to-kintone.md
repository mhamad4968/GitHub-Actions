# 旧フォーマット → kintone 初回移行仕様

**目的**: 現データが **`旧フォーマット` シート**にある前提で、**一度限り** kintone 入力アプリ（§6・§6c・`SPEC.md`）へ流し込む。**移行後の正は kintone のみ**（`SPEC.md` §3・§8）。

**関連**: `SPEC.md` §0b、§3、§8、§10。レイアウト正本は `shin-format-excel-layout.md`（**移行先の形**）。

---

## 1. 前提・禁止事項

- **読み取り元**: ブック内シート **`旧フォーマット`**（月1列・起票日／出納日など。`SPEC.md` §0b の行×列目安）。
- **列見出しの位置（浜田・2026-04-28）**: **ヘッダは行 2**。列名の並びは **C 列から始まる（起点セル C2）**。
- **A・B 列（浜田・2026-04-28）**: **`旧フォーマット` において** — **A 列はブランク**。**B 列は通し番号**（行の連番）。移行先では kintone の **レコード番号は別採番**のため、B は **突合・ログ用**に使うか、任意で「旧通番」フィールドへ写してもよい（必須ではない）。
- **データ先頭行（浜田・2026-04-28）**: **行 3 から**。**データ左端は C3**（ヘッダ行 2 の直下）。
- **旧シートに入っている数値は予算のみ（浜田・2026-04-28）**: **実績・消費率・予算修正を旧の月列からそのまま取り込まない**（誤コピー防止）。初回移行で埋めるのは原則 **予算**と **明細キー列**のみ。**実績**は空（または 0）で開始し、運用で **`支払内訳`**／入力に従う（`SPEC.md` §6c・§8）。**消費率**は計算に任せる。**予算修正**は旧に列がなければ空／0。旧に起票日・出納日などの**列があっても**、§4 で「参照のみ／移行しない」と明記する。
- **データの性質（浜田・2026-04-28）**: 当シートは **予算取得時に得た 2026 年度の実予算データ**が入っており、**初回移行では必ず参照・取り込み対象とする**（省略不可）。数値の信頼できる一次ソース（**予算部分に限る**）。
- **書き込み先**: kintone **入力アプリ**のレコード（明細 1 行＝1 レコード、月次サブテーブル 12 行・**各月 4 列相当**、`支払内訳` は §6c）。**旧シートの列並び・月の持ち方は kintone のフォームと異なる**。
- **禁止**: 移行完了後に **旧シートへ数値を戻す**、**Excel を継続正として同期**する（`SPEC.md` 確認 9）。

## 2. CSV 作成時の注意（フォーム相違・必読）

旧は **月 1 列型・起票／出納日**など、kintone 側は **12 ヶ月 ×（予算・実績・消費率・予算修正）＋`支払内訳`**（`SPEC.md` §6・§6c）と **フォームが一致しない**。

| リスク | 対策 |
|--------|------|
| **そのまま「名前を付けて保存 CSV」**すると列がズレ、**結合セル**で行が壊れる | **結合解除済みコピー**から export するか、**スクリプトでセル座標指定**で読む。**ヘッダは行 2、列見出し左端は C 列（C2）**（§1）。 |
| **旧の列順＝kintone のフィールド順**と誤認 | **§4 列対応表どおりに並べ替え・分割・集約**した **別物の中間 CSV** を作る（旧 CSV をそのまま REST に流さない）。 |
| **月の対応**（旧の暦月列 vs 年度 5 月始まり） | **5 月〜翌 4 月**の対応表を §3 または別表で明示し、**1 セルずつ**突合する。 |
| **旧は予算のみ** | **実績額を旧の月列から import しない**（旧に無い／別意味の可能性）。実績は kintone 運用で入力。旧に出納日等の列があれば §4 で **移行する／しない** を列ごとに固定する。 |
| **実績・出納日（移行後の正規ルート）** | 運用では **`支払内訳`** と支払日ベース（`SPEC.md` §8）。初回バッチで旧から実績を捏造しない。 |
| **消費率** | 旧から拾わず、移行後 **計算**に任せる（**§3** 変換方針）。 |

**AI・作業者への依頼**: CSV を生成する際は **必ず §4 列対応表を開き**、不明列は **推測で埋めない**（要確認フラグを立てる）。

## 3. 変換方針（確定レベル）

| 観点 | 方針 |
|------|------|
| **予算** | 旧シートの **各月の予算相当列**（**旧に入っているのは予算のみ**）を、移行先の **該当月の「予算」フィールド**（サブテーブル行）にマッピングする。 |
| **実績** | **初回移行では旧から実績額を埋めない**（旧は予算のみ）。kintone の月次「実績」は **空または 0** で開始。以降は **`支払内訳`** と支払日ベースでロールアップ（`SPEC.md` §6c・§8）。 |
| **消費率** | **入力しない**。移行後は計算フィールドまたは JS／バッチで再計算。 |
| **予算修正** | **各月列（I〜T）からは原則入れない**（旧は**予算のみ**が月列に入っている）。旧 **U 列「都度」**は変動費の**仮予算枠**であり、新フォームでは **月次の「予算修正」**で同趣旨を管理する（`SPEC.md` §6）。**U→kintone の初回写し方**は **§4c**（案 A 推奨: 単一フィールドに保持し運用で振替）。 |
| **明細キー** | 工種名称・工種コード・費用種別・摘要・会社等、旧の列→ kintone の同一意味フィールドへ **1:1 または合成ルール**で対応（下記 **§4** で列レター確定）。 |

### 4c. 「都度」列と予算修正（業務意味・初回移行）

**業務（浜田・2026-04-28）**

- **都度（U 列）**は **変動費**向けの**仮の予算**（例: 電話工事、PC 購入、周辺機器）。工種別に、事前に必要そうな分を取り、**足りなくなったら枠を増やす**などの運用があった。
- **新フォーマット／kintone** 側では、同種の増枠・振替を **月次の「予算修正」**で扱う（`SPEC.md` §6・`shin-format-excel-layout.md` の四つ柱）。

**初回移行で U 列を kintone にどう載せるか**（採用案を決めたら §4 の U 行と本節を更新する）

| 案 | 内容 | 備考 |
|----|------|------|
| **A（推奨・仕様ドラフト）** | 明細レコードに **単一数値フィールド**（例: `都度_仮予算_移行`）を用意し、**U 列をそのまま写す**。月次サブテーブルの **「予算修正」は月列（I〜T）由来では空／0**（月列は予算のみ）。都度分の月別への振替は **運用で予算修正に入力**。 | 検証しやすい。ダッシュで「都度残」と予算修正を並べられる。 |
| **B** | U の金額を **1 つの月行の「予算修正」だけ**に書き込む（**どの月に寄せるかは浜田指定**）。 | 実装は単純だが、**月の意味を誤解するリスク**があるため業務確認必須。 |
| **C** | 摘要・工種に応じ **複数月の予算修正へ按分** | ルールが重い。必要なら後続フェーズ。 |

**確定前の作業**: 実装は **案 A を既定**とし、浜田が **B または C** を選んだ場合は §4 の U 行と本表を改定する。

## 6. 検証・合算ルール

- **件数**: 旧のデータ行数（**行 3〜**、ヘッダ行 2 を除く）≒ kintone 明細レコード数（**1 旧行＝1 レコード**を原則。分割ルールがある場合は **§4** に記載）。
- **金額（初回の主突合）**: 旧は **予算のみ**のため、旧の **月別予算合計** と kintone の **該当月予算**合計を **月度ごと**に比較する。**実績の突合は初回移行の必須条件に含めない**（実績は移行後に蓄積）。
- **実績（移行後）**: 運用で **`支払内訳`** を用い、月次実績と整合を取る（`SPEC.md` §8）。
