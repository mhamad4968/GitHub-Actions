# セッション切替後 — 段階読解ラダー（AI 用）

**目的**: **プロジェクトに着手する前**に、**ルールと運用境界を五段階で理解**する。その**後**に、**プロジェクトごとに確認（仕様の小出し・§41・GO）**を積み、いきなり実装に入らないようにする。

**Cursor Project Rules**: `.cursor/rules/session-read-ladder-two-phase.mdc`（**alwaysApply: true**）が、新セッションで **第0手＝本ファイル通読**と **二段階（A→B）** を毎回想起する。

**浜田貼付の番号控え**: チャットで渡す本文の控えは **`chat-sessions/desktop-ai-emergency-read-pack/09-READ-01.txt` からファイル名の番号昇順**（リポ正本。Desktop でも **名前順＝読取順**）。セッション終了時に `npm run session-starter:sync-desktop` で **`C:\Users\mhamada202408224\Desktop\AI緊急用\`** に同名コピーされる。AI は **09-READ-01（見出し READ-01）手順 4** のとおり **10→…→15** を先に Readし、**14-READ-06（READ-06）直後に `【AI分業チェック】`**、**15-READ-07 直後に `【READ-07 読了】` 1 行**を出してから本ファイルを通読する（未使用ファイルはスキップ可＋**読んだ番号・理由**を 1 行）。

**憲法・ゲートとの関係**: `checkpoint-latest.md`「セッション切替後の自律復元」の **項番 -1 / -0** と **`npm run session:bootstrap`（項番 0）**は **従来どおり先**に通す（機械ゲート・憲法整合）。**本ファイルの「共通五段階」は bootstrap 成功の直後から開始**する。**矛盾時は checkpoint を優先**する。

## A. 共通五段階（プロジェクト着手前・ルール理解）

**仕様正本（`SPEC.md` 等）は読まない**。読むのは **現在地・合意・地図・索引・憲法境界**だけ。各段のあと **「事前準備用テンプレ」1 回**（下記）。

### 事前準備で必ず書く「理解したこと」

**共通五段階（第1〜5段）のテンプレでは、「ここまでで理解したこと」＝「ルール・運用境界で何が分かったか」だけ**を書く（**本題の仕様・674・予算列の話は書かない**。それは **B** に回す）。

**良い例（ルール理解）**: 「項番 -0 OK まで `session:bootstrap` に進まない」「Tier B は deploy 等で浜田 GO」「§41 は高リスク・高コスト・仕様分岐のとき 1 問」「§50-3-8 は複雑 customize **着手直前**に再実行」「**AI 分業**: 本体が統括・実行、Kimi/DeepSeek/OpenRouter は MCP として本体が直列呼び、**【AI分業チェック】**を READ-06 直後に出した」など。

**悪い例**: 「予実の月次はサブテーブルで…」← これは **B1** で書く。

| 段 | 名前 | Read するもの（範囲を守る） |
|----|------|------------------------------|
| **第1段** | 現在地 | `chat-sessions/checkpoint-latest.md` **冒頭〜「最終更新」行まで**（日付・5A/5B のラベル・次の一手の有無） |
| **第2段** | 直前の合意 | `chat-sessions/handoff-log.md` **末尾最大 3 ブロック**（無ければテンプレに「無し」） |
| **第3段** | 棚卸しの地図 | `SESSION-BOOTSTRAP-CHECKLIST.md` **冒頭〜「フェーズ 1」表の直前まで**（**フェーズ 1c / 1b の中身はまだ読まない**） |
| **第4段** | ルール索引 | `RULES-INDEX.md` の **「セッション切替・文脈復元」** の表（**そのブロックだけ**でよい） |
| **第5段** | 憲法境界 | `SESSION-BOOTSTRAP-CHECKLIST.md` の **「フェーズ 2 — ルール・憲法」** の表（2.1 行を含む）に加え、`AGENTS.md` の **§35-1**・**§41（見出し＋「一問」の意味が分かる量）**・**§52（Tier A/B）**・**§50-3（`### §50-3` 見出し〜`#### §50-3-3` 手前まで＝航海図と §51 の関係・CEO 差し替え）**・**§50-3-8（見出し＋1 段落）** … **READ-06 は第0手で既読のはず**なので本段テンプレで「分業でいま理解していること」を 2 行追記する |

**第5段のゴール（自己点検）**: テンプレの「理解したこと」に **次を自分の言葉で書けること**。

- **いつ Tier B・浜田 GO が要るか**
- **§41 を出すのはどんなときか**（データ破壊・高コスト・仕様の複数正解）
- **§50-3-8 をいつ再実行するか**（予実・計算ロジック・複雑 customize **着手直前**）
- **AI 分業**: 本体と Kimi / DeepSeek / OpenRouter の役割境界、**MCP 結果の検収は本体**、**§51 直列**、**浜田への実行押し付け禁止（TSB-024）**

**共通五段階が終わるまで**: `customize/` 編集・`kintone-add-app`・本番投入など **副作用のある操作はしない**。

1. **`session:bootstrap` exit 0** の直後から **A. 共通五段階（第1〜5段）**を順に踏む。**各段ごとに「事前準備用テンプレ」1 回**（**理解したこと＝ルール面のみ**）。

### 事前準備用テンプレ（**A. 共通五段階・第1〜5段**だけに使う）

```
【事前準備 第○段 完了】（例: 第3段）
- 読んだもの: （パス）／（見出し・表の範囲を **具体名で**）
- ルール・運用で理解したこと:（箇条 **2〜5**。仕様書の中身は書かない）
- 意図せずスキップしていないか:（指定範囲を全部 Read／offset 連鎖で抜けなし）
- ルール面でまだ曖昧なこと:（1〜2 点。無ければ「なし」）
- 次:（次の段番号。第5段なら「A 完了 → B0 へ」）
```

**禁止に近い省略**: 「全体を把握しました」**だけ**。**「理解したこと」がルール以外になっている**（仕様に滑っている）こと。
