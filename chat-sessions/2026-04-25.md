1. **「器のみ」方針は時短に効く**: PC 台帳 Day 3 は payout 追跡フィールド (assigned_to/at) を意図的に未追加 → Day 4 customize 設計時に再判断 = YAGNI 寄り判断 + 仕様書厳密踏襲が 11 分完成の要因
2. **Cursor CLI 既定モデル罠**: `agent` 素起動は `composer-2-fast` で Opus 4.7 ではない → 永続設定で固定 or `--model` 必須。CLI 利用ガイド (`docs/cursor-cli-usage.md`) で明文化
3. **§11-5 3 段階検証は cron 設定にも適用必須**: env -i + minimal PATH での実証で「5/1 06:30 cron 動作確実」を保証 = 朝 cron 障害の事前予防
4. **F-2 自己批判の即実装**: 自己批判で約束した目標を 同日中に実装 (G-2 = root_cause_confirmed 追加) で誠実度を担保 = 馴れ合い禁止の自己適用
5. **タスク完了報告のまとめ化**: 浜田 8:31 指示で per-task 報告 → 最後に 1 回まとめへ変更 = 浜田の認知負荷削減 + AI 集中時間延長
6. **自動検証スクリプトを「目標を立てた直後」に書け** (H-1): F-2 で 5月目標 #2 を立てた → G-2/G-5 で達成 → H-1 で **自動監視 script を即書く** = future regression 完封。立法 → 実装 → 監視の 3 連鎖を 30 分で
7. **TSB-016 = BREAKING 削除の脆弱性 (H-2 発見)**: BREAKING 削除直後の数時間は無関係 commit が削除を undone する事故の温床。post-commit で削除セクションが含まれていないか自動検知 hook が必要 (改善案 #20 / 5/22 検討)
8. **StrReplace tool は内部キャッシュで pre-truncation 版を保持する** (H-2 副次発見): truncate → StrReplace の順だと StrReplace が truncate を上書きして undone する。修復順序: **StrReplace 編集 → 最後に shell truncate** で確実反映
9. **設計書を未来予約に置く価値** (H-3): 5/22 で実装する script の設計書を **4/25 の今書く** = 5/22 当日の認知負荷削減 + 設計品質向上 (時間に追われない) + 浜田事前レビュー可能
