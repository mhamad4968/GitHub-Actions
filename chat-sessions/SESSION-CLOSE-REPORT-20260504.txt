【6.2 タスク種別 × 推奨 MCP（優先度順・案）】
| タスク | 推奨 | 使い方の要点 |
|--------|------|----------------|
| **GitHub（PR・Issue・Actions ログ）** | `user-github` | Issue 本文取得・チェック実行状況。**curl より gh 方針**（既存 skill と整合） |
| **社内／認証付き URL の取得** | `user-fetch` | `WebFetch` で落ちるときの保険。**直前に tool descriptor を Read** |
| **公開 Web の最新ドキュメント** | `user-tavily` または `user-duckduckgo-search` | バージョン依存の API 仕様確認。**1 クエリ 1 目的** |
| **CVE・脆弱性名の確認** | `user-cve-search` | ライブラリ名＋年で素早く |
| **長文下書き・多視点ラフ** | `user-kimi` | §50-3-10。本文は **本体が検収**してから貼る |
| **盲点・反例 1 問** | `user-deepseek` | §50-3-8。**編集ツールの直前**がコスパ最大 |
| **kintone レコード・スペース操作（API ラッパがある場合）** | `user-kintone` / `user-kintone-dev` | **フィールド取得・ゲスト権限**系。**デプロイは既存 npm スクリプトと役割分担**（二重経路に注意） |
| **Figma URL が添付された UI** | `user-figma` | **get_design_context** 前に descriptor。デザイン→コードは **プロジェクト規約に翻訳** |
| **複雑な分岐の思考ログ** | `user-sequential-thinking` | 長いトレードオフを **人に見せる形**にするときのみ（乱発しない） |
| **長期メモ（ユーザー嗜好）** | `user-memory` | **本当に跨ぎたい前提だけ**（ノイズ増に注意） |
